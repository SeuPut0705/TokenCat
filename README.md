# TokenCat

시스템 지표와 Codex·Claude Code 토큰 기록을 함께 표시하는 작은 macOS 메뉴 막대 앱입니다. macOS 13 이상, Swift·AppKit·SwiftUI만 사용합니다. RunCat의 이미지나 코드는 사용하지 않습니다.

## 실행

```sh
./build.sh
open dist/TokenCat.app
```

이미 실행 중이면 두 번째 실행은 기존 앱의 상세 화면을 열고 종료합니다. 앱을 다시 열면 설정 창을 엽니다.

## 화면

### 상세 화면

메뉴 막대 항목을 누르면 상세 화면이 팝오버로 열리고, Esc나 항목 재클릭으로 닫으면 직전 앱으로 포커스가 돌아갑니다. 헤더 ⋯ 메뉴의 `패널로 분리`(또는 빠른 메뉴에서 ⌥ `패널로 열기`)를 고르면 높이를 조절할 수 있는 패널(폭 420pt)로 열리며, 위치·크기를 기억하고 종료 때 열려 있었으면 다음 실행 때 포커스를 빼앗지 않고 다시 엽니다. 화면은 서체 5단계, 의미별 색 토큰, 한 벌의 상태 글리프, 4pt 격자를 메뉴 막대와 함께 씁니다. 한 사실은 한 곳에만 둡니다: 헤더는 상태, 출력 카드는 기록, 행은 세션, 아래쪽은 수집 상태를 말합니다.

- **헤더**: 픽셀 고양이 머리와 상태 문장(`입력 필요 2개 · 진행 1개`, `세션 1개 진행 중 · 도구 실행 1`, `로그 대기`, `진행 중인 세션 없음`). 우선순위는 입력 필요 > API 재시도 > 도구·진행 > 로그 대기입니다. 머리는 상태에 따라 표정이 바뀝니다. 톱니는 설정(⌘,), ⋯ 메뉴에는 패널로 분리(팝오버에서만)·설정…(⌘,)·활성 상태 보기·TokenCat 정보·TokenCat 종료(⌘Q)가 있습니다. 실측 설정 바로가기는 아래쪽 실측 경고 버튼과 첫 실행 카드에 있습니다.
- **출력 토큰**: 최근 5분 동안 로그에 기록된 출력 토큰 수와 5초 단위 막대입니다. 막대는 기록량이며 속도로 환산하지 않습니다. 눈금은 최고 막대가 2/3 이상 차도록 {1, 1.5, 2, 3, 4, 5, 6, 8}×10ⁿ에서 고르고 분 눈금을 둡니다. 두 클라이언트가 함께 기록하면 `Codex 1.2k · Claude Code 6.6k`처럼 나눠 보입니다. 오른쪽은 마지막 기록의 증가량과 시각이며, 마지막 기록 30초 뒤부터는 그 자리에서 대기 이유(`입력 대기 · 답변하면 계속 기록`, `계획 승인 대기`, API 재시도, `명령 실행 중` 같은 도구 범주, 진행, 로그 대기)를 말합니다. 5분 기록도 진행 세션도 없으면 한 줄로 접힙니다. ⓘ는 키보드로도 열 수 있습니다.
- **Codex 사용 한도**: 출력 카드 바닥 행입니다. Codex 로그에 마지막으로 기록된 사용률(`Codex 주간 한도 28% 사용`; 5시간·주간 창이 함께 기록되면 사용률이 더 높은 창), 초기화까지 남은 시간, 기록 나이를 보입니다. 실시간 잔여량이나 소진 예측이 아닙니다. 85% 이상 주황, 95% 이상 빨강이며, 초기화 시각이 지나면 `—`와 `초기화됨`을 하루 동안 보이고 숨깁니다. Claude Code는 한도를 로그에 남기지 않아 표시하지 않습니다.
- **세션 목록**: 진행 중인 세션을 위에 두며, 포인터가 목록 위에 있거나 메뉴가 열린 동안에는 순서를 바꾸지 않습니다. 출력은 상태가 아니라 사건이라 별도 칩이 없고, 방금(5초 안) 기록이 있으면 행에 초록 점과 `+617 tok · 방금`이, 그 뒤에는 점 없이 `+617 tok · 10초 전`처럼 마지막 기록이 보입니다.
  - 진행 행: 상태 칩(`입력 필요`·`계획 승인 대기`·`질문 답변 대기`·`API 재시도`·`명령 실행` 같은 도구 범주·`진행`·`로그 대기`), 프로젝트와 짧은 ID, 이번 턴 출력 누적량(가장 큼), 클라이언트·모델·Codex effort, 턴 경과시간(입력 필요 행은 `입력 대기 m:ss`), 마지막 기록, 컨텍스트(Codex는 기록된 창 기준 `컨텍스트 61% 사용`, 85% 이상 주황; Claude Code는 창 크기를 기록하지 않아 `컨텍스트 182k` 절대값)를 보입니다.
  - 속도 열은 보이는 진행 행 중 실측이 하나라도 있을 때만 나타나며, 모르는 값은 `—`이고 로그 시각으로 추정하지 않습니다.
  - 쉬는 행: 프로젝트, 클라이언트, 마지막 완료 턴 출력(`마지막 턴 4.8k`), 나이. `종료 기록 없음`·`중단`은 고리 글리프로 구분합니다.
  - 하위 에이전트는 정확한 부모 세션 아래에 트리 가이드로 이어집니다. 제목은 구별되는 역할·별명(Codex 역할·별명, Claude Code 사이드카의 `agentType`, Codex 자동 검토는 `자동 검토`)이고 공통 역할이면 ID 8자입니다. 오른쪽은 마지막 기록 나이와 이번 턴 출력입니다. 실행 중인 하위는 모두 보이고 로그 대기 하위는 `+N 하위 로그 대기`로 묶입니다.
  - 펼친 목록은 진행 중이 아닌 세션을 `오늘`·`어제`·`이번 주`·`이전`으로 나누고 `이전`은 접습니다. 행 높이는 고정이고 목록은 최대 264pt까지 보이며(패널은 남은 높이 전체) 나머지는 스크롤합니다.
- **행 상세와 메뉴**: 행을 클릭하거나 Return을 누르면 인라인 상세(세션 ID 복사, 에이전트, 모델, 실행 중인 도구 이름, 마지막 완료 턴 출력과 소요 시간, 기록 시점)가 열립니다. 두 값을 나누어 속도로 만들지 않습니다. 우클릭(VoiceOver 동작 포함)은 `세션 ID 복사`·`에이전트 ID 복사`·`재개 명령 복사`(`cd '<경로>' && claude --resume <ID>` 또는 `codex resume <ID>`, 메인 세션만. 경로나 ID에 백슬래시·제어 문자가 있으면 셸·터미널이 다르게 해석할 수 있어 제공하지 않음)·`기록 파일 Finder에서 보기`·`프로젝트 폴더 Finder에서 보기`입니다. 파일 내용은 열지 않습니다. 키보드는 ↑↓ 이동, Return·Space 상세, ⌘C ID 복사입니다(macOS 13에서는 목록을 한 번 클릭한 뒤 사용).
- **시스템**: 상자 없이 아래쪽에 CPU(30초 최고값 눈금)·메모리·저장 공간·배터리·네트워크(↓ 값 위, ↑ 아래, 10 미만은 소수 한 자리)를 미터와 함께 보입니다. 메모리 색은 사용률이 아니라 macOS 메모리 압력(정상·경고·위험)을 따릅니다. 영역을 누르면 활성 상태 보기를 엽니다. IP 주소는 도움말에서만 보여줍니다.
- **아래쪽**: 상태 항목 하나만 둡니다(AI 수집 지연 > 시스템 수집 지연 > 실측 문제 > 재시작 후 실측 표시 > `실시간`). 실측 문제는 원인별 버튼(`실측 꺼짐 · 포트 사용 중`, `실측 꺼짐 · 다른 TokenCat`, `실측 꺼짐 · 수집기 오류`, `실측 꺼짐 · 설정 충돌`, `실측 꺼짐 · 연결 실패`, `실측 미수신 · 확인 필요`)이고 누르면 설정의 실측 탭을 엽니다.
- **처음 실행·빈 화면·로딩**: 처음 한 번 실제 결과만 말하는 안내 카드(메타데이터만 사용, 실측 연결 결과와 백업 위치, 하지 않는 일)를 보이며 ✕로 닫습니다. 로딩 중에는 자리 표시 행을 보입니다. 기록 폴더가 없을 때와 기록이 없을 때를 구분하고, 폴더가 없으면 `다시 확인` 버튼과 Claude 웹·데스크톱 채팅은 수집하지 않는다는 안내를 보입니다.
- **접근성**: '대비 증가'에서 흐린 글자·테두리·점선 고리를 진하게 하고, 상태는 색과 모양을 함께 씁니다. 정보 글자는 4.5:1, 상태 글리프·미터는 3:1을 목표로 픽스처에서 측정했습니다(완료·최근 활동 없음 점은 장식으로 보고 대비 증가에서만 진하게 합니다). VoiceOver 로터와 행 라벨을 제공하고 동작 줄이기를 따릅니다.

### 메뉴 막대

표시 방식은 **최소**(고양이·AI 상태 마크·세션 수, 약 72pt, 고양이를 숨기면 약 49pt), **두 줄**(기본, 모든 항목 약 272pt), **한 줄**(모든 항목 약 410pt) 중에서 고릅니다. 최소 표시는 항목 목록과 관계없이 AI를 항상 보여 줍니다. 항목마다 폭을 고정해 값이 바뀌어도 위치가 흔들리지 않으며 흔한 최대값('100%', 세 자리 네트워크 값과 단위)도 줄이지 않고 그립니다.

CPU·메모리·저장 공간·배터리·업로드/다운로드·AI 세션 수를 표시합니다. 두 줄 표시는 네트워크 화살표 열을 고정하고 숫자를 오른쪽 정렬하며, 단위와 '%'는 작게 표시하되 생략하지 않습니다. 네트워크 값은 10 미만에서 소수 한 자리를 씁니다. 네트워크는 물리 Wi-Fi·Ethernet 인터페이스를 합산하며 로컬 루프백·VPN 가상 인터페이스는 제외합니다. 배터리가 없는 Mac에서는 배터리 항목을 숨깁니다.

AI 숫자는 진행 중인 최상위 세션 수(하위 에이전트는 부모에 포함)이며 첫 수집 전에는 `—`입니다. 진행이 없고 로그 대기만 있으면 로그 대기 세션 수를 흐린 글자로, 그 외에는 흐린 `0`을 보입니다. 마크는 상세 화면과 같은 글리프입니다: 보라 링(진행), 파란 둥근 사각(도구 실행), 회색 반원(로그 대기), 노란 `?`(입력 필요). 출력은 사건이라 마크가 없습니다. `종료 기록 없음`은 표시하지 않습니다. 마크 자리는 항상 비워 두어 숫자 위치가 움직이지 않습니다. 상세 화면이 열려 있으면 색을 빼고 모양만 라벨색으로 그리며, 대비 증가 설정에서는 채운 도구·입력 마크에 라벨색 테두리를 그리고 로그 대기 반원을 진하게 합니다. 툴팁에는 용량·AI 요약·조작 안내만 넣고 실시간 값은 VoiceOver 값으로 제공합니다.

우클릭(⌃클릭) 빠른 메뉴 맨 위에는 `AI 세션 · 입력 1 · 도구 1 · 진행 1`(없으면 `진행 중인 세션 없음`)과 급한 순서로 최상위 세션 최대 3개(`프로젝트 — 입력 대기 3분`, 분 단위)가 있고, 고르면 상세 화면에서 그 행을 선택합니다. 그 아래 열기(⌥ 패널로 열기) / 표시 방식 / 고양이 표시 / 움직임 기준 / 설정…(⌘,) / 활성 상태 보기 / TokenCat 정보 / 종료(⌘Q)가 있습니다.

### 고양이

움직임 기준은 **AI 활동 상태**(기본) / CPU 사용률 / AI 실측 속도 / 멈춤입니다. AI 활동 상태는 상태별 고정 박자이며 속도를 뜻하지 않습니다. 진행·도구 실행은 걷기(프레임당 0.15초), 새 출력 기록은 1.2초 달리기(달리는 중이나 끝난 뒤 1초 안의 새 출력은 달리기를 이어 감), 입력 필요는 정면으로 앉아 바라보기, 로그 대기는 앉기(6·9.5·4.5·11·7.5초 간격을 순환하며 깜빡임, 네 번째마다 두 번), 10분간 활동이 없으면 잠입니다. 잠은 20분 동안 숨 쉬며 작은 z와 큰 z를 번갈아 보이다가 큰 z로 고정되고 애니메이션 타이머를 멈춥니다. 깰 때 한 번 하품하고, 턴이 끝나 앉아 있을 때 한 번 만족한 듯 깜빡입니다. 걷기·달리기는 1초 이상 유지한 뒤에만 바뀌고 입력 필요는 즉시 바뀝니다. CPU 기준은 4% 미만이면 앉고 사용률이 높을수록 빠르게 움직이며, 실측 기준은 5초 이내 실측이 없으면 앉습니다. 예전 'AI 실측 속도'와 이전 버전이 기본으로 저장한 'CPU 사용률'은 한 번 AI 활동 상태로 옮기며, 이후 직접 고른 값은 유지합니다. 동작 줄이기가 켜져 있으면 자세만 바뀌고 하품·깜빡임·숨쉬기를 생략합니다. 고양이를 숨겼거나 화면이 잠들었거나 메뉴 막대가 가려지면 타이머를 멈추며, 그동안의 하품·만족 동작은 나중에 몰아서 재생하지 않습니다.

### 설정

설정은 도구 막대 탭 창이며 마지막 탭을 기억하고 높이를 내용에 맞춥니다. 값은 UserDefaults에 저장합니다.

- **일반**: 로그인 시 열기(기본 꺼짐, 켤 때만 macOS 로그인 항목(SMAppService)에 등록하고 실제 등록 상태를 다시 읽어 표시, /Applications 설치 권장). 알림: 턴 완료 / 입력 필요 / 입력 필요 알림에 소리(모두 기본 꺼짐, 켤 때만 권한 요청). 상세 패널 열기, `기본값으로 되돌리기…`(확인 후 실행, ⌘Z로 복원; 로그인 항목과 알림 권한은 바꾸지 않음).
- **메뉴 막대**: 1:1 미리보기(라이트·다크), 폭, 표시 방식, 항목 표시·순서와 약어. 순서는 끌어서 바꾸거나 VoiceOver 동작으로 바꿉니다. 배터리가 없는 Mac에서는 배터리 항목을 끄고, 고양이를 숨기면 마지막 항목은 숨길 수 없습니다.
- **고양이**: 표시, 움직임 기준, 상태별 자세 범례(포인터를 올리면 재생).
- **실측**: 수집기 상태, 다음 자동 재시도와 `지금 다시 시도`, 클라이언트별 수신·재시작 필요 여부, 백업 폴더와 Codex·Claude Code 설정 파일 Finder에서 보기(파일은 열지 않음). 설정이 바뀐 클라이언트는 그 클라이언트의 실측 전송(해석하지 못한 기록 포함)이 처음 도착하면 안내를 지웁니다. 24시간이 지나도록 오지 않으면, 설정 변경 뒤 그 클라이언트를 실제로 사용한 기록이 있을 때만 '이 버전에서 실측을 받지 못했습니다'로 바꾸고, 사용하지 않은 클라이언트는 조용히 둡니다.
- **정보**: 아이콘, 버전, 개인정보 문구, MIT 라이선스, 처음 실행 안내 다시 보기.

알림 제목은 `입력 필요 · 프로젝트` / `턴 완료 · 프로젝트` / `턴 중단 · 프로젝트`, 부제는 `Claude Code · 모델`, 완료 본문은 `12,480 tok · 4분 12초`이며 질문이나 응답 내용은 넣지 않습니다. 세션마다 입력 필요 알림과 턴 완료·중단 알림이 각각 최신 하나씩만 남고, 답하면 입력 필요 알림이 사라지며(다시 실행할 때 이전 실행이 남긴 해당 알림도 정리), 누르면 그 행을 선택합니다. 상세 화면이 실제로 보이는 동안에는 보내지 않습니다. 상세 화면이 보이고 VoiceOver가 켜져 있으면 입력 필요와 턴 완료를 5초에 최대 한 번 안내합니다.

### 자산

메뉴 막대 고양이(러너 v2, 매니페스트 v3)와 앱 아이콘 v2는 `Assets/Generator`의 Swift 코드로 결정적으로 생성하며 팔레트는 한 곳(`Palette.swift`)에서 정합니다. 러너는 흰 털·차콜 외곽선·코발트 목걸이의 픽셀 아트로 일곱 자세(앉기 2·잠 2·걷기 4·달리기 6·정면 앉기 2·하품 1·만족 2 프레임)를 갖고 32 × 20pt 칸에 흐림 없이 1:1로 그립니다. 잠의 z는 스프라이트에서 분리한 효과 레이어(`runner-v2-fx`)로, 메뉴 막대 보조 라벨색(대비 증가 시 라벨색)으로 그립니다. 프레임 시간·깜빡임 리듬도 매니페스트에서 읽습니다. 상세 화면 헤더와 처음 실행 안내 카드는 같은 픽셀 머리 네 가지(보통·깜빡임·경계·잠)를 쓰고, 설정의 정보 탭은 앱 아이콘을 보입니다. 앱 아이콘은 인디고에서 슬레이트로 이어지는 macOS 26 스타일 타일에 기존 고양이 마크(app-mark-v1, 내장 image_gen 원본)를 올렸고, 16·32px은 메뉴 막대 고양이와 같은 픽셀 머리입니다. macOS 13–15에서는 16·32px 아이콘이 다른 앱보다 조금 크고 그림자 없는 사각형으로 보일 수 있습니다. 벡터 마스터 v3는 미리보기만 생성하며 빌드에는 쓰지 않습니다. 생성 명령·팔레트·측정값·SHA-256(macOS 27.0.1·Swift 6.4 기준)은 `Assets/runner-v2.md`, `Assets/app-icon-v2.md`에 있습니다.

## 토큰 지표

`~/.codex/sessions`와 `~/.claude/projects`의 로컬 JSONL 기록에서 세션·모델·출력 토큰·진행 상태를 읽습니다. 로그 시각의 차이로 토큰 생성 속도를 추정하지 않습니다. 턴 전체 시간에는 도구 실행과 대기가 포함되므로 이를 생성 속도로 표시하지 않으며, 진단 출력에도 로그 시각으로 만든 속도를 남기지 않습니다. 턴 시간은 클라이언트가 기록한 값만 쓰고 출력과 나누지 않습니다. 실제 실측 데이터가 없으면 속도는 `—`입니다.

TokenCat은 시작할 때 로컬 수집기의 준비 상태를 확인한 뒤 Codex `~/.codex/config.toml`의 OpenTelemetry exporter와 Claude Code `~/.claude/settings.json`의 실측 환경 변수를 자동으로 추가합니다. 두 클라이언트는 **다음 새 실행부터** 적용되며 진행 중인 작업은 재시작하지 않습니다. TokenCat이 실행 중이어야 데이터를 받을 수 있습니다. 수집기가 준비되지 않으면 클라이언트 설정을 변경하지 않습니다.

수집기는 `127.0.0.1:16493`에서 OTLP HTTP/JSON의 `/v1/logs`, `/v1/metrics`, `/v1/traces`를 받습니다. 외부 인터페이스에는 열지 않으며 웹페이지 Origin을 가진 요청을 거부합니다. 프롬프트·응답 본문 로깅은 끄고, 모델·세션/에이전트/요청 식별자·시간·출력 토큰 등 허용된 메타데이터만 메모리에 보관합니다. 원문 요청을 파일로 저장하지 않습니다. 실측은 최근 256개에 더해 (제공사, 세션, 에이전트, 모델)마다 최신 1건을 최대 128개까지 보관하며, 넘치면 하위 에이전트 항목부터 비우므로 하위 에이전트 요청이 몰려도 메인 세션의 마지막 속도가 사라지지 않습니다. `/v1/diagnostics`에는 수신 건수와 service·metric 이름·단위·인식 여부를 최대 64개 유지하고, 인식하지 못한 서비스는 span·event 이름과 속성 키만 남기며 값은 남기지 않습니다. HTTP 본문 2MB, 동시 연결 16개, 요청 제한 5초로 제한하며 종료 시 연결을 해제합니다. 포트를 쓸 수 없으면 5초·30초 후, 이후 2분마다 포트가 풀릴 때까지 다시 시도하고, 다른 TokenCat이 수집 중인지 다른 앱이 포트를 쓰는지 구분해 표시합니다.

표시 단위는 실측 기준에 따라 구분합니다.

- **생성 tok/s**: Codex 서버가 제공한 실제 토큰 간 시간(TBT)의 역수입니다. `codex.responses_api_engine_service_tbt.duration_ms` 또는 `codex.responses_api_engine_iapi_tbt.duration_ms`를 사용합니다.
- **모델 tok/s**: 서버 지표가 여러 관측을 묶어 전달하면 토큰 간 시간의 평균으로 계산합니다. 관측 횟수와 계측 구간을 도움말에 표시합니다. 여러 요청의 통계를 개별 세션 속도로 귀속하지 않습니다.
- **요청 tok/s**: Claude Code가 같은 `api_request` 사건에 제공한 출력 토큰 수를 실제 성공 요청 시간으로 나눈 처리율입니다. 첫 응답 대기·추론을 포함합니다. trace만 제공된 경우에는 재시도가 포함된 요청 시간임을 표시합니다. 순수 생성 속도와 측정 기준이 다릅니다.

첫 토큰 지연과 서버 inference 시간이 제공되면 도움말에서 원값을 확인할 수 있습니다. 첫 토큰 지연만으로 생성 속도를 만들지 않습니다. Codex SSE 이벤트 처리 시간을 모델 생성 시간으로 사용하지 않습니다. 최신 완료 실측을 표시하므로 진행 중 출력의 순간 속도를 의미하지 않습니다. Codex 데스크톱(codex-app-server)은 로그·trace를 보내지만 요청별 생성 시간 형식을 확인하지 못해 속도를 `—`로 표시합니다.

제공사·세션·에이전트 식별자가 정확히 일치할 때만 로그 행에 실측을 붙입니다. 모델 이름이나 시간의 근접성으로 연결하지 않습니다. Claude Code는 하위 에이전트 요청에 항상 에이전트 식별자를 붙이므로, 에이전트 식별자가 없는 요청은 같은 세션의 유일한 메인 로그에 연결합니다. 한 행에 여러 모델의 실측이 있으면 행의 현재 모델 실측을 우선하므로 제목 생성 같은 보조 요청이 현재 모델 속도를 가리지 않습니다. 세션 식별자가 없는 서버 지표는 **모델 실측** 행으로 표시하고, 로그에 연결되지 않은 식별자는 **요청 실측** 행으로 유지합니다. 같은 세션의 모델이 바뀌면 현재 모델과 이전 측정 모델을 구분합니다. 공식 [Codex OpenTelemetry 설정](https://learn.chatgpt.com/docs/config-file/config-advanced)과 [Claude Code 모니터링 명세](https://code.claude.com/docs/en/monitoring-usage)를 따릅니다. 클라이언트 버전·서버 응답에 따라 지표나 식별자가 제공되지 않을 수 있습니다.

연결 전 원본 설정은 `~/Library/Application Support/TokenCat/telemetry-backups/`에 접근 제한을 적용해 백업합니다. 인증·모델·훅 등 기존 설정과 파일 권한을 유지합니다. 기존 외부 실측 목적지와 충돌하면 덮어쓰지 않습니다. 진단 명령 `--disconnect-telemetry`는 연결 후 사용자 변경이 없는 경우 원본 바이트를 복구하며, 변경이 있으면 자동 복구를 거부하고 사용자 설정을 보존합니다. 복구는 다음 클라이언트 실행부터 적용됩니다. 앱을 다시 시작하면 자동 연결을 다시 설정합니다.

### 세션과 상태

Codex·Claude Code 하위 에이전트도 별도로 수집하며 정확한 부모 세션 식별자(Claude Code는 공유 세션 ID, Codex는 루트 스레드 ID)로 묶습니다. 포크된 Codex 로그가 부모의 세션 메타데이터를 다시 기록해도 파일 이름의 스레드 ID로 자기 신원을 유지하며, 다시 기록된 부모의 사용 한도·압축 기록은 제외합니다.

진행 중 표시는 열린 턴의 마지막 로그 기록 이후 허용 시간 안에 있을 때입니다. 모델 응답 대기는 10분, Claude Code 도구 실행은 15분, Codex 도구 실행은 120초이며 모든 종류의 로그 기록이 반영됩니다. 허용 시간이 지나면 `로그 대기`로, 마지막 기록 후 30분이 지나면 `종료 기록 없음`으로 바뀝니다. Claude Code가 질문(AskUserQuestion)이나 계획 승인(ExitPlanMode)을 기다리면 `입력 필요`이며 `로그 대기`로 바뀌지 않고 24시간 동안 기록이 없으면 `종료 기록 없음`이 됩니다. Codex Plan 모드의 질문(`request_user_input`)도 같은 규칙으로 `입력 필요`이며, 비동기 `request_user_input_async`는 일반 도구로 취급합니다. 권한 확인 요청은 로그에 남지 않아 표시하지 않습니다. OS 프로세스 생존 여부를 뜻하지 않으며, 파일 수정 시각은 활동 시각으로 사용하지 않고 변경 감지에만 사용합니다.

실행 중인 도구는 이름만으로 명령 실행·파일 작업·웹 조회·하위 에이전트·MCP·질문·기타로 구분합니다. 도구 입력은 읽지 않으며 원래 도구 이름은 도움말에만 표시합니다. Claude Code API 재시도 기록에서는 재시도 횟수·최대 횟수·대기 시간·네트워크 끊김 여부만 읽고(`재시도 2/10 · 4초 후`), 오류 메시지는 저장하지 않으며 다음 응답이 오거나 턴이 끝나면 해제합니다.

Codex 사용 한도는 로그에 기록된 사용률·주기·초기화 시각을 기록 시각과 함께 씁니다. 컨텍스트는 Codex가 마지막 응답의 입력 토큰과 같은 기록의 모델 컨텍스트 창을, Claude Code가 입력·캐시 토큰 합계를 씁니다. Claude Code 창 크기는 모델 이름으로 추정하지 않으며, 압축은 완료 기록 시각만 표시합니다.

토큰 증가는 로그가 기록한 시점에만 반영하며 중복 사용량은 다시 더하지 않습니다. Codex는 응답 직후 남기는 `token_usage_record`(응답별·턴 누적 출력)를 사용하므로 도구 실행이 끝나기를 기다리지 않습니다. `response_id`로 중복을 제거하며, 이 기록이 없는 이전 버전 로그에서만 `token_count`를 사용합니다. Claude Code는 메시지가 끝날 때 기록하므로 생성 중인 토큰은 메시지 완료 후 반영됩니다. Claude Code 로그가 길면 최대 16MB 범위에서 열린 턴의 입력을 역방향으로 찾아 그 지점부터 읽습니다. 현재 턴 전체 구간을 확인할 수 없을 때만 누적량을 `—`로 표시합니다. 턴 종료는 Claude Code의 종료 기록, 하위 에이전트의 턴 종료 도구 결과, 도구 호출 없는 최종 응답, API 오류·중단 기록으로 확인합니다. 최종 응답 뒤에 기록이 이어지면(Stop 훅 등) 같은 턴을 이어갑니다. 완료·중단을 확인하면 현재 턴 경과시간과 누적량을 지웁니다. 세션 복원으로 다시 기록된 이전 기록은 다시 반영하지 않습니다.

### 수집 범위와 갱신

Claude Code의 터미널·데스크톱 실행 경로를 수집합니다. Claude 웹·일반 데스크톱 채팅은 Claude Code와 다른 경로이므로 수집 대상이 아닙니다. 최근 로그 파일을 Codex 32개, Claude Code 메인 32개·하위 에이전트 32개까지 읽으며 이후 추가된 부분만 수집합니다. 진행 중이거나 1시간 이내 기록이 있는 세션은 더 새로운 파일이 많아도 계속 추적합니다(최대 128개). 로그 디렉터리의 파일 변경 이벤트(FSEvents)로 기록 즉시 다시 읽으며(최대 초당 4회), 1초 주기 확인과 5초 주기 새 파일 확인을 함께 유지합니다. 1MB를 넘는 한 줄은 내용을 읽지 않고 앞부분의 도구 호출 식별자만 확인합니다. 긴 Codex 로그는 최대 16MB 범위의 모델·턴 메타데이터를 역방향으로 확인합니다. 누락된 토큰 구간은 재구성하지 않습니다. 시스템·로그 수집과 로컬 실측은 각각 독립된 백그라운드 큐에서 처리하며, 메모리 압력은 커널의 압력 단계(정상·경고·위험)를 읽습니다.

TokenCat 자체는 모델 호출·계정 로그인을 하지 않으며, 로그인 항목 등록과 알림은 설정에서 직접 켠 경우에만 합니다.

실제 환경에서는 Codex 0.160.0의 서버 TBT 수신과 네이티브 화면 표시를 확인했습니다. Claude Code에서도 인증된 실제 요청의 출력 토큰·성공 요청 시간·첫 토큰 시간을 수신하고, 동일한 세션·요청 식별자의 로컬 로그와 대조했습니다. 예를 들어 `claude-opus-5-5`의 200 출력 토큰 / 4,532 ms는 요청 처리율 44.1 tok/s이며, 순수 생성 속도를 뜻하지 않습니다. 실측 데이터가 없는 경우에는 숫자를 표시하지 않습니다.

## 검증 명령

```sh
dist/TokenCat.app/Contents/MacOS/TokenCat --self-test
dist/TokenCat.app/Contents/MacOS/TokenCat --diagnose
dist/TokenCat.app/Contents/MacOS/TokenCat --connect-telemetry
dist/TokenCat.app/Contents/MacOS/TokenCat --telemetry-readings
dist/TokenCat.app/Contents/MacOS/TokenCat --disconnect-telemetry
dist/TokenCat.app/Contents/MacOS/TokenCat --live-check
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot work/dashboard.png
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot work/dashboard-light.png --light
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot-fixtures work/fixtures
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot-menubar work/menubar.png
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot-menubar work/menubar-states.png --fixtures
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot-settings work/settings.png --pane all
dist/TokenCat.app/Contents/MacOS/TokenCat --telemetry-lifecycle-checks
dist/TokenCat.app/Contents/MacOS/TokenCat --notification-status
```

`--diagnose`는 시스템 수치·토큰 및 실측 메타데이터만 출력합니다(프로젝트 전체 경로 포함, 이 Mac에서만 확인용). `--telemetry-readings`는 실행 중인 TokenCat 수집기의 실측 메타데이터를 확인합니다. `--snapshot`은 실제 로컬 지표로 상세 패널 이미지를 저장합니다. `--snapshot-fixtures`는 합성 데이터로 상세 화면 상태(입력 필요·재시도·도구 범주·로그 대기·조용함·한도·컨텍스트·하위 세션·펼친 목록·행 상세·키보드 선택·빈 화면·로딩·실측 경고·첫 실행·대비 증가) 이미지를 다크·라이트로 저장하며 로컬 로그·수집기·호스트 정보를 읽지 않습니다. `--snapshot-menubar <png> [--light] [--inline|--minimal] [--highlighted] [--fixtures] [--no-runner]`는 같은 네이티브 렌더러로 메뉴 막대 미리보기를 저장합니다. `--fixtures`는 라이트·다크와 열림 상태 네 열을 모두 그리므로 `--light`·`--highlighted`는 실데이터 미리보기에만 적용됩니다. `--snapshot-settings <png> [--light] [--pane general|menubar|cat|telemetry|about|all] [--fixtures]`는 설정 창 탭을 화면 밖에서 렌더합니다. `--telemetry-lifecycle-checks [port]`는 실제 루프백 포트로 수집기 시작·포트 점유 구분·재시도·`지금 다시 시도`를 검사하므로 기본 `--self-test`와 분리돼 있습니다. `--notification-status`는 알림 권한 상태를 묻지 않고 읽기만 합니다. 첫 CPU·네트워크 샘플은 이전 카운터가 없으므로 미측정이며 두 번째 샘플부터 표시됩니다.

`--self-test`는 로그의 중복·부분 기록·시간 경계·재개된 세션·다중 세션 분리·모델 변경·하위 에이전트 경로·턴 종료·입력 필요·재시도·한도·컨텍스트 등을 검증하고, 러너 매니페스트 v3·자세별 프레임 수·타이밍·효과 레이어·픽셀 머리·0/255 알파, OTLP 파싱·식별자 연결·속도 산출, 표시 상태·그룹·메뉴 막대 폭·설정 이전, 설정 보존·백업·복구·충돌·부분 저장 실패를 확인합니다.

`--live-check`는 자동 갱신 주기로 실제 시스템과 로컬 로그를 약 6초간 수집합니다. 갱신 간격·중복 시작 방지·종료 후 갱신 차단을 JSON으로 출력하며 실패하면 종료 코드 1을 반환합니다. 모델을 호출하지 않습니다.

현재 빌드는 이 Mac에서 실행하도록 ad-hoc 서명됩니다. App Store 배포·Developer ID 서명·공증·자동 업데이트는 포함하지 않습니다.

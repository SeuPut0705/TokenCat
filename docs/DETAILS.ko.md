# TokenCat 자세한 동작

[README](../README.ko.md)로 돌아가기

시스템 지표와 함께 코딩 에이전트(Codex, Claude Code, OpenCode, Gemini CLI, Qwen Code, Copilot CLI, Amp, Cline·Roo Code·Kilo Code, omp·Pi, Factory Droid, Cursor, Grok, Hermes, OpenClaw, Goose, Kimi Code)의 세션·출력 토큰·실측 속도·사용 한도를 표시하는 작은 macOS 메뉴 막대 앱입니다. macOS 13 이상, Swift·AppKit·SwiftUI만 사용합니다. RunCat의 이미지나 코드는 사용하지 않습니다. Windows 버전은 [Windows](#windows)에서 다룹니다.

이 문서는 화면·수집·실측의 동작 규칙을 빠짐없이 적은 참고 문서입니다. 소개와 미리보기는 [README](../README.ko.md)에 있습니다. 아래 명령은 모두 저장소 루트에서 실행합니다.

## 실행

```sh
./build.sh
open dist/TokenCat.app
```

이미 실행 중이면 두 번째 실행은 기존 앱의 상세 화면을 열고 종료합니다. 앱을 다시 열면 설정 창을 엽니다. 릴리스로 설치하는 방법과 처음 열 때의 Gatekeeper 허용은 [README › 설치](../README.ko.md#설치)에 있습니다.

## 화면

### 상세 화면

메뉴 막대 항목을 누르면 상세 화면이 팝오버로 열리고, Esc나 항목 재클릭으로 닫으면 직전 앱으로 포커스가 돌아갑니다. 헤더 ⋯ 메뉴의 `패널로 분리`(또는 빠른 메뉴에서 ⌥ `패널로 열기`)를 고르면 높이를 조절할 수 있는 패널(폭 420pt, 최소 높이 510pt)로 열리며, 위치·크기를 기억하고 종료 때 열려 있었으면 다음 실행 때 포커스를 빼앗지 않고 다시 엽니다. 화면은 서체 5단계, 의미별 색 토큰, 한 벌의 상태 글리프, 4pt 격자를 메뉴 막대와 함께 씁니다. 한 사실은 한 곳에만 둡니다: 헤더는 상태, 한도 카드는 한도, 출력 카드는 기록, 행은 세션, 아래쪽은 수집 문제를 말합니다. 출력 카드의 `지금 속도`만 예외로, 세션 하나의 최근 실측을 그대로 다시 보이며 합치지 않습니다.

- **헤더**: 픽셀 고양이 머리와 상태 문장(`입력 필요 2개 · 진행 1개`, `세션 1개 진행 중 · 도구 실행 1`, `로그 대기 1개 · 3분째 새 기록 없음`, `진행 중인 세션 없음`). 우선순위는 입력 필요 > API 재시도 > 도구·진행 > 로그 대기입니다. 머리는 상태에 따라 표정이 바뀝니다. 톱니는 설정(⌘,), ⋯ 메뉴에는 패널로 분리(팝오버에서만)·설정…(⌘,)·활성 상태 보기·TokenCat 정보·TokenCat 종료(⌘Q)가 있습니다. 실측 설정 바로가기는 아래쪽 실측 경고 버튼과 첫 실행 카드에 있습니다.
- **사용 한도**: 헤더 바로 아래 한도 카드에 계정마다 한 블록을 둡니다. 왼쪽 열은 제공사를 첫 계정에 한 번만 적고, 계정 이름과 출처 한 줄을 둡니다. 오른쪽 열은 창 이름·막대·사용률·초기화까지 남은 시간을 정렬하며(`5시간 ▬▬▬ 36% ↻ 4시간 53분`), 5시간이 주간보다 먼저 옵니다. 제공사 사이는 전체 너비의 가는 선으로, 같은 제공사의 계정 사이는 들여쓴 가는 선으로 나눕니다. 2분 미만의 [실시간 확인](#실시간-한도-확인) 값은 초록 점과 `실시간`, 그보다 오래된 값은 기록 나이(`5분 전`)로 보이고, omp·Pi가 기록한 값이면 그 이름을 붙입니다(`omp · 4분 전`). 소진 예측이 아닙니다. 85% 이상 주황, 95% 이상 빨강이고 10분 넘게 지난 값은 숫자를 흐리게 그리며, 초기화 시각이 지나면 `—`와 `초기화됨`을 하루 동안 보이고 숨깁니다. `사용`과 `후 초기화`는 화면이 아니라 도움말과 VoiceOver에 남깁니다. Codex는 실시간 확인 값이나 로그에 기록된 값, Claude는 실시간 확인 값, [상태 표시줄 브리지](#claude-사용-한도와-상태-표시줄-브리지)로 받은 값, Claude 데스크톱 앱의 사용량 기록이며, 둘 다 [omp·Pi 사용량 기록](#omppi-사용량-기록)도 씁니다. 기록 나이는 실시간·브리지 값이면 TokenCat이 받은 시각, 데스크톱 앱·omp·Pi 기록이면 그 기록 시각 기준입니다. 초기화 시각은 만들어 내지 않습니다. 데스크톱 앱 기록에는 없고 실시간 응답에도 없을 수 있으며, 그때는 초기화 열을 비웁니다. 제공사 이름이 `Claude`인 것은 한도가 Claude 계정 단위이기 때문입니다.
  - 진행 중인 세션의 계정, 없으면 가장 최근 활동 계정, 클라이언트 기본 계정, 이전 계정 미확인 데이터 순으로 고릅니다. 알려진 계정이 여럿이면 이메일의 @ 앞부분이나 ID 끝부분을 쓰고, 줄인 이름이 같아지면 전체 이름을 보입니다. 도움말과 VoiceOver에는 전체 이름을 남깁니다. 귀속과 대체 규칙은 [구독 계정](#구독-계정)에 있습니다.
- **출력 토큰**: 최근 5분 동안 로그에 기록된 출력 토큰 수를 카드 제목 줄에, 5초 단위 막대를 그 아래에 둡니다. 막대는 기록량이며 속도로 환산하지 않습니다. 눈금은 최고 막대가 2/3 이상 차도록 {1, 1.5, 2, 3, 4, 5, 6, 8}×10ⁿ에서 고르고 분 눈금을 두며, 막대 눈금 값은 그래프 도움말에 있습니다. 여러 클라이언트가 함께 기록하면 제목 옆에 `Claude Code 6.6k · Codex 1.2k`처럼 많은 순서로 나눠 보이고, 다 들어가지 않는 클라이언트는 가장 많은 하나만 남을 때까지 `외 N`으로 접고 그래도 모자라면 뺍니다. 제목 아래 줄은 마지막 기록의 증가량과 시각이며, 마지막 기록 30초 뒤부터는 대기 이유(API 재시도, `명령 실행 중` 같은 도구 범주, 진행, 로그 대기)를 말하고 자리가 있으면 기록 옆에 함께 둡니다. 입력·계획 승인을 기다리는 세션은 헤더와 그 행이 이미 말하므로 여기서 되풀이하지 않습니다. 5분 기록도 진행 세션도 없으면 한 줄로 접힙니다. ⓘ는 키보드로도 열 수 있습니다.
- **지금 속도**: 제목 아래 줄 끝에 `지금 속도 · Install guide 55.6 생성 tok/s`처럼 그 행의 제목(하위 에이전트는 프로젝트)을 붙여 보입니다. 보이는 진행 행(하위 에이전트 포함) 가운데 2분 안에 받은 가장 최근 실측 한 건이며, 그 행의 현재 모델로 잰 값만 쓰고 재시작을 기다리는 클라이언트는 뺍니다. 세션끼리 합치거나 평균내지 않고 로그 시각으로 만들지 않습니다. 그런 실측이 없으면 진행·도구 실행·API 재시도 행이 있을 때만 `속도 실측 없음`(도움말에 이유: 최근 2분 실측 없음, 이전 모델 기준, 재시작 필요)을 두고, 입력·로그 대기뿐이거나 진행이 없으면 숨깁니다. 폭이 모자라면 라벨, 이어서 제목을 뺍니다. 도움말에는 세션 제목·프로젝트·모델·측정 시점과 근거를, VoiceOver에는 단위 종류·값·제목을 알립니다.
- **세션 목록**: 진행 중인 세션을 위에 두며, 포인터가 목록 위에 있거나 메뉴가 열린 동안에는 순서를 바꾸지 않습니다. 출력은 상태가 아니라 사건이라 별도 칩이 없고, 방금(5초 안) 기록이 있으면 행에 초록 점과 `+617 tok · 방금`이, 그 뒤에는 점 없이 `+617 tok · 10초 전`처럼 마지막 기록이 보입니다.
  - 진행 행: 상태 글리프는 글리프 열에, 세션 제목(없으면 프로젝트)과 짧은 ID는 모든 행이 함께 쓰는 글자 열에 두고, 이번 턴 출력 누적량(가장 큼)을 보입니다. 둘째 줄은 상태를 말로(`계획 승인 대기`·`질문 답변 대기`·`API 재시도`·`명령 실행` 같은 도구 범주·`진행`·`로그 대기`) 시작해 프로젝트(제목이 세션 자신의 것일 때)·클라이언트·모델·Codex effort를 보이고 턴 경과시간(입력 필요 행은 기다린 시간 `m:ss`)으로 끝납니다. 그 아래 마지막 기록과 컨텍스트(Codex는 기록된 창 기준 `컨텍스트 61% 사용`, 85% 이상 주황; Claude Code는 창 크기를 기록하지 않아 `컨텍스트 182k` 절대값)를 보입니다.
  - 속도 칸은 보이는 진행 행 중 (재시작을 기다리지 않는 클라이언트의) 실측이 하나라도 있을 때만 나타납니다. 모르는 값은 `— tok/s`(구분선으로 보이지 않도록 단위를 붙임)이고 로그 시각으로 추정하지 않으며, 이 표시는 생성 중일 수 있는 진행·도구 실행·API 재시도 행에만 둡니다. 입력·로그 대기 행은 실측 값이 있을 때만 보이고, 속도 칸만을 위해 셋째 줄을 늘리지 않습니다.
  - 쉬는 행: 세션 제목(없으면 프로젝트)과 그 뒤의 프로젝트, 클라이언트, 마지막 완료 턴 출력(`마지막 턴 4.8k`), 나이(폭이 고정돼 `마지막 턴`이 행마다 같은 자리에 옵니다). `종료 기록 없음`·`중단`은 고리 글리프로 구분하고, 자리가 있으면 클라이언트 뒤에 작은 글자로도 적습니다.
  - 하위 에이전트는 정확한 부모 세션 아래에 트리 가이드로 이어집니다. 제목은 구별되는 역할·별명(Codex 역할·별명, Claude Code 사이드카의 `agentType`, Codex 자동 검토는 `자동 검토`)이고, 없거나 공통 역할이면 `하위 에이전트 · a2222222`처럼 ID 8자를 옆에 둡니다. 오른쪽은 마지막 기록 나이와 이번 턴 출력입니다. 실행 중인 하위는 모두 보이고 로그 대기 하위는 `+N 하위 로그 대기 ⌄`로 묶이며, 누르면 그 묶음에서 목록을 펼칩니다.
  - 접힌 목록은 공개 행 하나로 끝납니다: 접어 둔 세션이 있으면 `세션 N개 모두 보기 ⌄`, `+N` 줄이 보여 주지 않는 하위만 있으면 `하위 N개 더 보기 ⌄`, 펼친 뒤에는 `접기 ⌃`입니다. 펼친 목록은 진행 중이 아닌 세션을 `오늘`·`어제`·`이번 주`·`이전`으로 나누고 `이전`은 접습니다. 행 높이는 고정이고 목록은 최대 312pt까지 보이며(패널은 남은 높이 전체) 나머지는 스크롤합니다.
- **행 상세와 메뉴**: 행을 클릭하거나 Return을 누르면 인라인 상세(세션 ID 복사, 에이전트, 모델, 실행 중인 도구 이름, 마지막 완료 턴 출력과 소요 시간, 기록 시점)가 열리고, 해당하면 `재개 명령 복사`·`Finder에서 보기`(프로젝트 폴더, 없으면 기록 파일) 버튼이 함께 나옵니다. 두 값을 나누어 속도로 만들지 않습니다. 우클릭(VoiceOver 동작 포함)은 `세션 ID 복사`·`에이전트 ID 복사`·`재개 명령 복사`(`cd '<경로>' && claude --resume <ID>` 또는 `codex resume <ID>`, 메인 세션만. 경로나 ID에 백슬래시·제어 문자가 있으면 셸·터미널이 다르게 해석할 수 있어 제공하지 않음)·`기록 파일 Finder에서 보기`·`프로젝트 폴더 Finder에서 보기`입니다. 그 밖의 재개 명령은 `opencode --session`, `gemini --resume`, `copilot --resume`, `amp threads continue`, `grok --resume`, `hermes --resume`, `kimi -r`, `goose session --resume --session-id`이고, Qwen Code·Cline·omp·Droid·Cursor·OpenClaw와 다른 제품 이름으로 보이는 행(TRAE CLI, OpenClaude, Qoder, Kilo Code, MiMo Code, Kimi Work, Kimi CLI 등)에는 없습니다. 파일 내용은 열지 않습니다. 키보드는 ↑↓ 이동, Return·Space 상세, ⌘C ID 복사, ⌘⇧C 재개 명령 복사입니다(macOS 13에서는 목록을 한 번 클릭한 뒤 사용).
- **시스템**: 상자 없이 아래쪽에 CPU·메모리·저장 공간·배터리·네트워크(↓ 값 위, ↑ 아래, 10 미만은 소수 한 자리)를 같은 길이의 미터와 함께 보입니다. CPU는 30초 최고값이 지금 값보다 5 이상 높을 때만 눈금으로 표시합니다. 메모리 색은 사용률이 아니라 macOS 메모리 압력(정상·경고·위험)을 따릅니다. 영역을 누르면 활성 상태 보기를 엽니다. IP 주소는 도움말에서만 보여줍니다.
- **아래쪽**: 상태 항목 하나만 둡니다(AI 수집 지연 > 시스템 수집 지연 > 실측 문제 > `Codex·Claude Code 재시작 후 속도 표시`). 이런 항목이나 업데이트 알림이 있을 때만 보이고, 모두 정상이면 줄을 숨기며 확인 주기와 마지막 실측 수신은 헤더 문장의 도움말에 있습니다. 실측 문제는 원인별 버튼(`실측 꺼짐 · 포트 사용 중`, `실측 꺼짐 · 다른 TokenCat`, `실측 꺼짐 · 수집기 오류`, `실측 꺼짐 · 설정 충돌`, `실측 꺼짐 · 연결 실패`, `실측 미수신 · 확인 필요`)이고 누르면 설정의 실측 탭을 엽니다. 새 버전이 있으면 세션 상태와 겨루지 않는 조용한 한 줄(`새 버전 1.0.0`, `업데이트`, 그 버전만 숨기는 닫기)을 더하고, 진행 중에는 `업데이트 내려받는 중 45%`·`설치 중…`, 실패하면 `업데이트 실패`와 `다시 시도`·릴리스 페이지 열기를 보입니다([업데이트와 배포](#업데이트와-배포)).
- **처음 실행·빈 화면·로딩**: 처음 한 번 실제 결과만 말하는 안내 카드를 항목마다 한 줄로 보이고 자세한 설명은 그 줄의 도움말에 둡니다(메타데이터만 사용; 실측 연결 결과와, 추가했으면 `백업 보기`, 연결을 건너뛰거나 실패하거나 수집기가 꺼졌으면 그 이유와 강조된 `설정 열기`; Claude Code 상태 표시줄을 감쌌는지는 그 줄의 도움말; 인터넷 요청은 GitHub 새 버전 확인·내려받기와 OpenAI·Anthropic 사용량 확인뿐이며 설정에서 끌 수 있음). ✕로 닫습니다. 로딩 중에는 자리 표시 행과 값 폭의 자리 표시, 아래쪽 `준비 중`을 보입니다. 최근 5분 기록이 없으면 출력 카드는 한 줄로 접히고, 이전 출력이 있을 때만 오른쪽에 `마지막 출력 …`을 둡니다. 기록 폴더가 없을 때와 기록이 없을 때를 구분하며, 제목은 둘 다 클라이언트 이름 없이 씁니다(`아직 코딩 에이전트 세션 기록이 없습니다`, `코딩 에이전트 기록 폴더를 찾지 못했습니다`). 기록이 없으면 새 세션 안내를, 폴더가 없으면 지원하는 클라이언트 이름 한 줄(찾는 폴더는 그 줄의 도움말에 있음)과 `다시 확인` 버튼을 보이고, 둘 다 Claude 웹·데스크톱 채팅은 수집하지 않는다고 알립니다.
- **접근성**: '대비 증가'에서 흐린 글자·테두리·점선 고리를 진하게 하고, 상태는 색과 모양을 함께 씁니다. 정보 글자는 4.5:1, 상태 글리프·미터는 3:1을 목표로 픽스처에서 측정했습니다(완료·최근 활동 없음 점은 장식으로 보고 대비 증가에서만 진하게 합니다). VoiceOver 로터와 행 라벨을 제공하고 동작 줄이기를 따릅니다.

### 메뉴 막대

표시 방식은 **최소**(캐릭터·AI 상태 마크·세션 수, 약 72pt, 캐릭터를 숨기면 약 49pt), **두 줄**(기본, 기본 여섯 항목 약 272pt), **한 줄**(같은 항목 약 410pt) 중에서 고릅니다. 최소 표시는 항목 목록과 관계없이 AI를 항상 보여 줍니다. 항목마다 폭을 고정해 값이 바뀌어도 위치가 흔들리지 않으며 흔한 최대값('100%', 세 자리 네트워크 값과 단위)도 줄이지 않고 그립니다.

CPU·메모리·저장 공간·배터리·업로드/다운로드·AI 세션 수를 표시합니다. 평균 속도 항목(기본 꺼짐, 항목 목록에서는 `평균 속도 · AVG`, 무엇의 평균인지는 그 줄의 도움말에 적음)은 직접 켜야 하는 항목으로, `지금 속도`가 받아들이는 세션별 실측 속도(2분 안, 그 세션의 현재 모델, 재시작을 기다리지 않는 클라이언트)를 모든 클라이언트에 걸쳐 산술 평균합니다. 실측값만 평균하며 속도를 추정하지 않습니다. 라벨 자리에는 실측을 보탠 클라이언트를 빠른 순서(클라이언트별 평균 기준)로 보여 줍니다. 하나면 그 아이콘 하나, 여럿이면 최대 세 개를 1pt 간격으로 나란히, 잘리지 않게 그립니다. 도움말에는 이름을 붙입니다(`평균 속도 55.6 토큰/초 · Codex, Claude Code`). 실측이 없으면 `AVG`(한 줄에서는 속도계 기호)와 `—`로 표시합니다. 100 tok/s부터는 메뉴 막대에서 소수점을 빼고(`312 tok/s`), 이 항목은 두 줄에서 56pt, 한 줄에서 91pt를 차지해 아이콘 세 개 옆의 네 자리 속도도 줄이지 않습니다. 두 줄 표시는 네트워크 화살표 열을 고정하고 숫자를 오른쪽 정렬하며, 단위와 '%'는 작게 표시하되 생략하지 않습니다. 라벨과 단위는 라벨색 72%(대비 증가 시 80%)로 그려 막대의 밝은·어두운 모양을 따르므로, 보조 라벨색처럼 색이 비치는 막대에서 평평한 회색이 되지 않습니다. 네트워크 값은 10 미만에서 소수 한 자리를 씁니다. 네트워크는 물리 Wi-Fi·Ethernet 인터페이스를 합산하며 로컬 루프백·VPN 가상 인터페이스는 제외합니다. 배터리가 없는 Mac에서는 배터리 항목을 숨깁니다.

AI 숫자는 진행 중이거나 입력을 기다리는 최상위 세션 수(하위 에이전트는 부모에 포함)이며 첫 수집 전에는 `—`입니다. 입력을 기다리는 세션이 있으면 내가 답할 그 세션 수만 보여 주고, 전체 내역은 툴팁과 VoiceOver 값에 남깁니다. 진행이 없고 로그 대기만 있으면 로그 대기 세션 수를 흐린 글자로, 그 외에는 흐린 `0`을 보입니다. 마크는 상세 화면과 같은 글리프입니다: 보라 링(진행), 파란 둥근 사각(도구 실행), 회색 반원(로그 대기), 노란 `?`(입력 필요). 출력은 사건이라 마크가 없습니다. `종료 기록 없음`은 표시하지 않습니다. 마크 자리는 항상 비워 두어 숫자 위치가 움직이지 않습니다. 상세 화면이 열려 있으면 색을 빼고 모양만 라벨색으로 그리며, 대비 증가 설정에서는 채운 도구·입력 마크에 라벨색 테두리를 그리고 로그 대기 반원을 진하게 합니다. 툴팁에는 용량·AI 요약·조작 안내만 넣고 실시간 값은 VoiceOver 값으로 제공합니다.

우클릭(⌃클릭, VoiceOver에서는 항목의 `빠른 메뉴` 동작) 빠른 메뉴 맨 위에는 `AI 세션 · 입력 1 · 도구 1 · 진행 1`(없으면 `진행 중인 세션 없음`)과 급한 순서로 최상위 세션 최대 3개(`프로젝트 — 입력 대기 3분`, 분 단위)가 있고, 고르면 상세 화면에서 그 행을 선택합니다. 더 있으면 이어서 `그 외 9개 세션…`이 상세 화면을 엽니다. 그 아래 열기(⌥ 패널로 열기) / 표시 방식 / 캐릭터(캐릭터 선택·메뉴 막대에 표시) / 움직임 기준 / (새 버전이 있으면) `업데이트 1.0.0 설치…` / 설정…(⌘,) / 활성 상태 보기 / TokenCat 정보 / TokenCat 종료(⌘Q)가 있습니다. 업데이트 항목은 내려받기·설치 중에는 숨기고, 다시 해도 나아지지 않는 실패(임시 위치에서 실행, 쓰기 권한 없음, 설치 파일·검증 정보 없음 등) 뒤에는 `업데이트 1.0.0 릴리스 페이지…`로 바뀌어 릴리스 페이지를 엽니다. 더 새 버전을 찾으면 그 실패를 지우고 다시 설치를 제안합니다.

### 캐릭터

모든 캐릭터(고양이·강아지·햄스터·펭귄·로봇)가 같은 규칙으로 움직이며, 아래에서는 고양이로 설명합니다. 움직임 기준은 **AI 활동 상태**(기본) / CPU 사용률 / AI 실측 속도 / 멈춤입니다. AI 활동 상태는 상태별 고정 박자이며 속도를 뜻하지 않습니다. 진행·도구 실행은 걷기(프레임당 0.15초), 새 출력 기록은 1.2초 달리기(달리는 중이나 끝난 뒤 1초 안의 새 출력은 달리기를 이어 감), 입력 필요는 정면으로 앉아 바라보기, 로그 대기는 앉기(6·9.5·4.5·11·7.5초 간격을 순환하며 깜빡임, 네 번째마다 두 번), 10분간 활동이 없으면 잠입니다. 잠은 20분 동안 숨 쉬며 작은 z와 큰 z를 번갈아 보이다가 큰 z로 고정되고 애니메이션 타이머를 멈춥니다. 깰 때 한 번 하품하고, 턴이 끝나 앉아 있을 때 한 번 만족한 듯 깜빡입니다. 걷기·달리기는 1초 이상 유지한 뒤에만 바뀌고 입력 필요는 즉시 바뀝니다. CPU 기준은 4% 미만이면 앉고 사용률이 높을수록 빠르게 움직이며, 실측 기준은 5초 이내 실측이 없으면 앉습니다. 예전 'AI 실측 속도'와 이전 버전이 기본으로 저장한 'CPU 사용률'은 한 번 AI 활동 상태로 옮기며, 이후 직접 고른 값은 유지합니다. 동작 줄이기가 켜져 있으면 자세만 바뀌고 하품·깜빡임·숨쉬기를 생략합니다. 고양이를 숨겼거나 화면이 잠들었거나 메뉴 막대가 가려지면 타이머를 멈추며, 그동안의 하품·만족 동작은 나중에 몰아서 재생하지 않습니다.

### 설정

설정은 도구 막대 탭 창이며 마지막 탭을 기억하고 높이를 내용에 맞춥니다. 값은 UserDefaults에 저장합니다.

- **일반**: 로그인 시 열기(기본 꺼짐, 켤 때만 macOS 로그인 항목(SMAppService)에 등록하고 실제 등록 상태를 다시 읽어 표시, /Applications 설치 권장). 알림: 턴 완료 / 입력 필요 / 입력 필요 알림에 소리(모두 기본 꺼짐, 켤 때만 권한 요청), 권한 줄(macOS가 알림이나 소리를 막으면 그 줄에 `알림 설정 열기`). 맨 아래 따로 둔 구역(메뉴 막대·캐릭터 탭까지 되돌리므로)의 `기본값으로 되돌리기…`(확인 후 실행, ⌘Z로 복원; 항목 순서·표시, 표시 방식, 캐릭터, `새 버전 알림`을 포함한 알림 선택을 되돌리고 로그인 항목, `새 버전 자동 확인`, macOS 알림 권한은 그대로 둠).
- **메뉴 막대**: 1:1 미리보기(라이트·다크), 폭, 프리셋(최소·AI 집중·시스템 모니터·전체 한 줄: 표시 방식·보이는 항목과 순서·캐릭터 표시를 한 번에 정함, 어느 것과도 맞지 않으면 `사용자 지정`), 표시 방식, 항목 목록: 맨 위에 캐릭터(스프라이트가 붙은 체크 상자, 메뉴 막대가 늘 맨 앞에 그리므로 자리 고정), 이어서 항목 표시·순서와 약어. 순서는 끌어서 바꾸거나 VoiceOver 동작으로 바꿉니다. 캐릭터와 항목 중 최소 하나는 표시되므로 마지막 하나는 숨길 수 없습니다. 캐릭터와 AI만 그리는 최소 표시에서는 항목 줄을 흐리게 하고 끌 수 없게 합니다. 배터리가 없는 Mac에서는 배터리 항목을 끕니다.
- **캐릭터**: 캐릭터(고양이·강아지·햄스터·펭귄·로봇, 모두 같은 자세와 박자), 움직임 기준, 상태별 자세 범례(포인터를 올리면 재생). 캐릭터 표시 여부는 메뉴 막대 탭의 항목 목록에 있습니다.
- **실측**: 수집기 상태(듣고 있으면 테두리 체크와 `켜짐 · 127.0.0.1:16493`, 자동 재시도와 `지금 다시 시도`는 그 아래 따로 한 줄), 클라이언트별 수신(`아직 받은 실측 없음`은 점선 원)·재시작 필요 여부와 그 클라이언트 설정 파일을 Finder에서 보여 주는 폴더 단추, `Claude 한도` 줄(최근 수신, Claude 데스크톱 앱 기록, omp·Pi 기록, 아직 받지 못함, statusLine 형식이 달라 건너뜀, 원래 명령을 몰라 상태 표시줄이 비어 보일 수 있음, 원래 명령을 백업 기록에서 다시 만듦), 상태 표시줄로는 사용량 한도만 받는다는 안내, `백업 폴더 보기`, 이어서 `연결` 줄의 `연결 해제…`(확인 후 `--disconnect-telemetry`와 같은 일을 메인 스레드 밖에서 하고 자동 연결을 멈춤, 해제한 뒤에는 `다시 연결`)와 `실시간 한도 확인`(기본 켜짐. ### 언어

화면·메뉴·알림·도움말·VoiceOver 안내와 명령줄 출력은 영어와 한국어를 지원하며, 실행할 때 한 번 정해 종료할 때까지 유지합니다. 앱 번들에 `en`·`ko` 지역화가 있어 macOS가 고른 언어를 따르므로 **시스템 설정 › 일반 › 언어 및 지역 › 응용 프로그램**에서 TokenCat만 따로 고를 수 있고, 따로 고르지 않으면 선호 언어 가운데 한국어와 영어 중 먼저 나오는 쪽, 둘 다 없으면 영어입니다. 명령마다 `--language ko|en`을 붙이면 그 언어로 고정합니다. 날짜·숫자 형식은 표시 언어에 이 Mac의 지역을 더해 씁니다. GitHub 업데이트 요청의 `Accept-Language`는 표시 언어와 관계없이 `en`입니다.

## 토큰 지표

`~/.codex/sessions`(`$CODEX_HOME/sessions` 먼저)와 `~/.claude/projects`(먼저 `CLAUDE_CONFIG_DIR`가 쉼표로 나열한 폴더마다, 이어서 `~/.config/claude/projects` 또는 `$XDG_CONFIG_HOME/claude/projects`)의 로컬 JSONL 기록에서 세션·모델·출력 토큰·진행 상태를 읽습니다. Claude Code의 `<세션>.orphaned-*.jsonl` 사본은 건너뜁니다. 로그 시각의 차이로 토큰 생성 속도를 추정하지 않습니다. 턴 전체 시간에는 도구 실행과 대기가 포함되므로 이를 생성 속도로 표시하지 않으며, 진단 출력에도 로그 시각으로 만든 속도를 남기지 않습니다. 턴 시간은 클라이언트가 기록한 값만 쓰고 출력과 나누지 않습니다. 실제 실측 데이터가 없으면 속도는 `—`입니다.

Codex나 Claude Code 형식으로 기록하는 제품도 같은 방식으로 읽고 자기 이름으로 보입니다. **TRAE CLI**(`~/.trae/cli/sessions`, `TRAEX_SESSIONS_DIR`)는 Codex 형식, **OpenClaude**(`~/.openclaude/projects`, `OPENCLAUDE_CONFIG_DIR`)와 **Qoder**(`~/.qoder/projects`, `~/.qoder-cn/projects`, IDE의 `~/Library/Application Support/Qoder/SharedClientCache/cli/projects`)는 Claude Code 형식입니다. 포크의 한도는 그 구독의 한도가 아니므로 이 행에는 Codex·Claude 사용 한도가 붙지 않고 재개 명령도 없습니다. 실측 설정은 여전히 `~/.codex/config.toml`과 `~/.claude/settings.json`만 고칩니다.

다른 코딩 에이전트는 설정 없이 데이터 폴더로 자동 인식합니다. OpenCode·Kilo Code·MiMo Code(`~/.local/share/opencode`, `~/.local/share/kilo`, `~/.local/share/mimocode`), Gemini CLI(`~/.gemini/tmp`, macOS 샌드박스에서는 `~/.cache/.gemini/tmp`), Qwen Code(`~/.qwen/projects`), Copilot CLI(`~/.copilot/session-state`), Amp(`~/.local/share/amp/threads`), Cline·Roo Code·Kilo Code·Zoo Code·IBM Bob(모든 VS Code 계열 에디터의 `globalStorage/<확장>/tasks`, `~/.cline/data/tasks`, `~/.cline/data/sessions`), omp·Pi(`~/.omp/agent/sessions`, `~/.omp/profiles/<이름>/agent/sessions`마다, `~/.pi/agent/sessions`), Factory Droid(`~/.factory/sessions`), Cursor(`~/.cursor/projects`), Grok(`~/.grok/sessions`), Hermes(`~/.hermes`), OpenClaw(`~/.openclaw/agents`, 예전 `~/.clawdbot`·`~/.moltbot`), Goose(`~/.local/share/goose/sessions`), Kimi Code(`~/.kimi-code/sessions`, Kimi 데스크톱 앱의 `~/Library/Application Support/kimi-desktop/daimon-share/daimon/runtime/kimi-code/home/sessions`, 보관된 kimi-cli의 `~/.kimi/sessions`)입니다. 클라이언트 자신의 변수가 있으면 그 위치를 씁니다: `XDG_DATA_HOME`, `OPENCODE_DB`, `KILO_DB`, `MIMOCODE_HOME`, `MIMOCODE_DB`, `GEMINI_CLI_HOME`, `QWEN_RUNTIME_DIR`, `QWEN_HOME`, `COPILOT_HOME`, `AMP_DATA_DIR`, `CLINE_DIR`, `CLINE_DATA_DIR`, `CLINE_SESSION_DATA_DIR`, `PI_CODING_AGENT_DIR`, `PI_CONFIG_DIR`(설정돼 있으면 `$XDG_DATA_HOME/omp`도), `PI_CODING_AGENT_SESSION_DIR`(Pi), `FACTORY_HOME_OVERRIDE`, `CURSOR_CONFIG_DIR`, `GROK_HOME`, `HERMES_HOME`, `OPENCLAW_STATE_DIR`, `OPENCLAW_HOME`, `OPENCLAW_PROFILE`, `GOOSE_PATH_ROOT`, `KIMI_CODE_HOME`, `KIMI_SHARE_DIR`. 기본 폴더도 함께 봅니다. 각 에이전트의 로그 읽기는 제공사 목록(`TokenProviders.swift`의 `TokenProvider.all`, Windows는 `TokenProvider.All`)에 등록되어 있고, 위에 적은 에이전트는 모두 아래와 같이 읽습니다. 인식한 에이전트는 AI 항목의 클라이언트별 수에 이름이 나옵니다. 실측은 Codex·Claude Code·Gemini CLI·Qwen Code를 연결하고, 실시간 한도와 상태 표시줄 브리지는 Codex·Claude Code 전용이며, 평균 속도 항목과 AI 세션 수는 읽는 모든 에이전트를 포함합니다.

- **Gemini CLI**: `~/.gemini/tmp/<프로젝트>/chats`(macOS 샌드박스 `SANDBOX=sandbox-exec`에서는 `~/.cache/.gemini/tmp`)의 `session-*.jsonl` 대화(이어 쓰기 전의 예전 `session-*.json` 스냅숏 포함)와 `chats/<세션>/` 폴더의 하위 에이전트 로그를 읽고, 프로젝트는 폴더의 `.project_root`에서 가져옵니다. 턴은 프롬프트부터 도구 호출이 없는 응답까지이며, Gemini CLI는 도구 호출을 끝난 뒤에 기록하므로 도구만 요청한 응답은 도구 실행 중으로 보입니다. 출력은 후보 토큰과 생각 토큰의 합입니다. 기다리는 질문·권한 확인과 생성 시간은 기록되지 않아 `입력 필요`는 표시하지 않고, 속도는 연결된 뒤 Gemini CLI 자체 실측으로만 표시합니다(아래). 새 기록 없이 열린 턴은 10분(도구 실행 중이면 15분) 뒤 `로그 대기`로 바뀝니다.
- **Qwen Code**: `~/.qwen/projects/<프로젝트>/chats`의 대화와 `<프로젝트>/subagents/<세션>/`의 백그라운드 하위 에이전트를 읽습니다(`QWEN_RUNTIME_DIR`·`QWEN_HOME`이 있으면 그 위치). 도구 호출과 결과가 바로 기록되므로 실행 중인 도구가 보이고, 기다리는 질문(`ask_user_question`)·계획 승인(`exit_plan_mode`)은 `입력 필요`로 보입니다. 컨텍스트는 기록된 창 대비 비율이며, 후보 토큰에 이미 포함된 추론 토큰은 다시 더하지 않습니다. 생성 시간은 기록되지 않으며, 속도는 연결된 뒤 Qwen Code 자체 실측으로만 표시합니다(아래).
- **Copilot CLI**: `~/.copilot/session-state/<세션>/` 폴더마다의 `events.jsonl`(예전 `session-state/<세션>.jsonl` 포함, `COPILOT_HOME`이 있으면 그 위치)을 읽고, 프로젝트는 세션 시작 기록이나 `workspace.yaml`에서 가져옵니다. 턴은 내 메시지부터 `session.task_complete`, 또는 마지막 응답이 도구를 요청하지 않은 턴 끝까지이며, `abort`·오류·종료는 중단으로 봅니다. 실행 중인 도구가 보이고, 기다리는 권한 확인이나 `ask_user`는 `입력 필요`로 보입니다. 출력 토큰은 응답마다의 `outputTokens`이며, 생성 시간이 담긴 요청별 사용량은 로그에 기록되지 않아 속도는 표시하지 않습니다. 열린 턴의 `inuse.<PID>.lock`이 모두 끝난 프로세스를 가리키면 `종료 기록 없음`으로 바뀝니다.
- **Amp**: `~/.local/share/amp/threads`의 `T-*.json` 스레드 파일(`AMP_DATA_DIR`이 있으면 `AMP_DATA_DIR/threads`)을 바뀔 때마다 통째로 다시 읽습니다. 턴은 마지막 응답의 상태로 정합니다. 생성 중이거나 도구를 기다리면 진행, `end_turn`이면 완료, 취소·오류면 중단이며, `blocked-on-user` 도구는 `입력 필요`로 보입니다. 출력 토큰은 응답마다의 `usage`(없으면 `usageLedger`)를 기록 시각에 더하고, 프로젝트는 스레드의 첫 작업 트리입니다. 생성 시간이 기록되지 않아 속도는 표시하지 않습니다.

Kimi Code가 kimi-cli에서 이미 옮겨 온 세션은 Kimi Code 쪽 사본으로 한 번만 보입니다.

TokenCat은 시작할 때 로컬 수집기의 준비 상태를 확인한 뒤 Codex `~/.codex/config.toml`의 OpenTelemetry exporter와 Claude Code `~/.claude/settings.json`의 실측 환경 변수를 자동으로 추가하고, Claude Code `statusLine` 명령을 [상태 표시줄 브리지](#claude-사용-한도와-상태-표시줄-브리지)로 감쌉니다. `~/.gemini`나 `~/.qwen`이 있으면 Gemini CLI `~/.gemini/settings.json`·Qwen Code `~/.qwen/settings.json`(없으면 만듦)의 `telemetry` 객체에도 `enabled: true`, `target: "local"`, `otlpEndpoint: "http://127.0.0.1:16493"`, `otlpProtocol: "http"`, `logPrompts: false`(두 클라이언트 모두 끄지 않으면 프롬프트 본문을 기록함)를 넣고 다른 키는 모두 유지합니다. Gemini CLI·Qwen Code 파일이 순수 JSON이 아니거나(두 클라이언트는 주석을 허용하지만 TokenCat은 주석을 유지할 수 없음) 키가 중복되거나 `telemetry`가 객체가 아니거나, 이미 다른 곳으로 보내고 있으면(자체 `otlpEndpoint`, `otlpLogsEndpoint`/`otlpTracesEndpoint`/`otlpMetricsEndpoint`, `outfile`, `target: "gcp"`, 또는 엔드포인트 없이 기본 `localhost:4317`로 보내는 `enabled: true`) 그대로 둡니다. 그 클라이언트만 건너뛰고 이유를 설정 › 실측에 표시하며, 다른 클라이언트는 그대로 연결합니다. `GEMINI_TELEMETRY_*`·`QWEN_TELEMETRY_*` 환경 변수는 이 설정보다 우선하며 TokenCat은 이를 볼 수 없습니다. 모든 클라이언트는 **다음 새 실행부터** 적용되며 진행 중인 작업은 재시작하지 않습니다. TokenCat이 실행 중이어야 데이터를 받을 수 있습니다. 수집기가 준비되지 않으면 클라이언트 설정을 변경하지 않습니다. 연결한 뒤 설치한 클라이언트는 다음 TokenCat 실행 때 같은 백업 아래에서 연결에 더해집니다.

수집기는 `127.0.0.1:16493`에서 OTLP HTTP/JSON의 `/v1/logs`, `/v1/metrics`, `/v1/traces`와 상태 표시줄 브리지의 `/v1/claude/status`를 POST(`Content-Type: application/json`)로 받고, TokenCat 자신의 확인용 `/health`, `/v1/readings`, `/v1/diagnostics`에는 GET으로만 답합니다. 본문은 `Content-Length`나 `Transfer-Encoding: chunked`로 받으며(Gemini CLI·Qwen Code의 Node exporter는 길이를 보내지 않음), 둘 다 있거나 다른 전송 인코딩이거나 chunk 형식이 깨졌거나 마지막 chunk 뒤에 바이트가 남은 요청은 거부합니다. 외부 인터페이스에는 열지 않으며 웹페이지 Origin을 가졌거나 `Host`가 `127.0.0.1`·`localhost`가 아닌 요청을 거부합니다(DNS 리바인딩 페이지가 읽지 못하도록). 프롬프트·응답 본문 로깅은 끄고, 모델·세션/에이전트/요청 식별자·시간·출력 토큰 등 허용된 메타데이터만 메모리에 보관합니다. 원문 요청을 파일로 저장하지 않으며, `/v1/claude/status`에서는 사용 한도 숫자만 남기고 나머지를 버립니다(디스크에 남는 것은 그 숫자뿐입니다). 실측은 최근 256개에 더해 (제공사, 세션, 에이전트, 모델)마다 최신 1건을 최대 128개까지 보관하며, 넘치면 하위 에이전트 항목부터 비우므로 하위 에이전트 요청이 몰려도 메인 세션의 마지막 속도가 사라지지 않습니다. `/v1/diagnostics`에는 수신 건수와 service·metric 이름·단위·인식 여부를 최대 64개 유지하고, 인식하지 못한 서비스는 span·event 이름과 속성 키만 남기며 값은 남기지 않습니다. HTTP 본문 2MB(`/v1/claude/status`는 64KB, 넘으면 413, chunk 형식은 그만큼을 더 넘지 못함), 동시 연결 16개, 요청 제한 5초로 제한하며 종료 시 연결을 해제합니다. 포트를 쓸 수 없으면 5초·30초 후, 이후 2분마다 포트가 풀릴 때까지 다시 시도하고, 다른 TokenCat이 수집 중인지 다른 앱이 포트를 쓰는지 구분해 표시합니다.

표시 단위는 실측 기준에 따라 구분합니다.

- **생성 tok/s**: Codex 서버가 제공한 실제 토큰 간 시간(TBT)의 역수입니다. `codex.responses_api_engine_service_tbt.duration_ms` 또는 `codex.responses_api_engine_iapi_tbt.duration_ms`를 사용합니다.
- **모델 tok/s**: 서버 지표가 여러 관측을 묶어 전달하면 토큰 간 시간의 평균으로 계산합니다. 관측 횟수와 계측 구간을 도움말에 표시합니다. 여러 요청의 통계를 개별 세션 속도로 귀속하지 않습니다.
- **요청 tok/s**: Claude Code가 같은 `api_request` 사건에 제공한 출력 토큰 수를 실제 성공 요청 시간으로 나눈 처리율이거나, Gemini CLI(`gemini_cli.api_response`)·Qwen Code(`qwen-code.api_response`)는 응답의 `output_token_count`(`total_token_count`로 생각 토큰을 따로 셌음이 보이면 `thoughts_token_count`를 더함)를 요청부터 스트림 끝까지인 `duration_ms`로 나눈 값, 또는 OpenCode·omp·Grok·Hermes·Goose·Kimi Code가 로그에 기록한 응답의 출력 토큰 수를 그 요청 시간으로 나눈 값입니다. 첫 응답 대기·추론을 포함합니다. trace만 제공된 경우에는 재시도가 포함된 요청 시간임을 표시합니다. 순수 생성 속도와 측정 기준이 다릅니다.

첫 토큰 지연과 서버 inference 시간이 제공되면 도움말에서 원값을 확인할 수 있습니다. 첫 토큰 지연만으로 생성 속도를 만들지 않습니다. Codex SSE 이벤트 처리 시간을 모델 생성 시간으로 사용하지 않습니다. 최신 완료 실측을 표시하므로 진행 중 출력의 순간 속도를 의미하지 않습니다. Codex 데스크톱(codex-app-server)은 로그·trace를 보내지만 요청별 생성 시간 형식을 확인하지 못해 속도를 `—`로 표시합니다.

제공사·세션·에이전트 식별자가 정확히 일치할 때만 로그 행에 실측을 붙입니다. 모델 이름이나 시간의 근접성으로 연결하지 않습니다. Claude Code는 하위 에이전트 요청에 항상 에이전트 식별자를 붙이므로, 에이전트 식별자가 없는 요청은 같은 세션의 유일한 메인 로그에 연결합니다. Gemini CLI·Qwen Code는 하위 에이전트 요청을 부모 세션 ID로 보내므로 메인 대화 요청만 읽어(Gemini CLI는 `role: "main"`, 예전 버전은 role 없음, Qwen Code는 `subagent_name`이 없는 요청) 그 세션의 유일한 메인 로그에 연결하며, Gemini CLI의 라우팅·루프 감지 같은 보조 요청도 건너뜁니다. 한 행에 여러 모델의 실측이 있으면 행의 현재 모델 실측을 우선하므로 제목 생성 같은 보조 요청이 현재 모델 속도를 가리지 않습니다. 세션 식별자가 없는 서버 지표는 **모델 실측** 행으로 표시하고, 로그에 연결되지 않은 식별자는 **요청 실측** 행으로 유지합니다. 같은 세션의 모델이 바뀌면 현재 모델과 이전 측정 모델을 구분합니다. 공식 [Codex OpenTelemetry 설정](https://learn.chatgpt.com/docs/config-file/config-advanced), [Claude Code 모니터링 명세](https://code.claude.com/docs/en/monitoring-usage), [Gemini CLI 실측](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/telemetry.md), [Qwen Code 실측](https://github.com/QwenLM/qwen-code/blob/main/docs/developers/development/telemetry.md)을 따릅니다. 클라이언트 버전·서버 응답에 따라 지표나 식별자가 제공되지 않을 수 있습니다.

연결 전 원본 설정은 `~/Library/Application Support/TokenCat/telemetry-backups/`에 접근 제한(폴더 0700, 파일 0600)을 적용해 백업합니다. 인증·모델·훅 등 다른 설정과 파일 권한을 유지합니다. 기존 외부 실측 목적지와 충돌하면 덮어쓰지 않습니다. 진단 명령 `--disconnect-telemetry`는 연결 후 변경이 없는 설정 파일의 원본 바이트를 복구하고 브리지 스크립트와 원래 명령 파일을 지웁니다. 연결 후 수정된 파일은 지금 바이트를 백업 폴더에 `before-disconnect-<시각>-<백업 이름>`(0600)으로 남긴 뒤 TokenCat 항목만 되돌립니다. Codex는 TokenCat이 끝에 붙인 `[otel]` 표와 그 앞 빈 줄을 바이트 그대로이고 다른 키가 없을 때 지우고, Claude Code는 `env`에서 아직 TokenCat 값을 가진 키를 백업의 값으로 되돌리거나(없었으면 지움) TokenCat이 `0`으로 바꾼 본문 로깅 키를 백업의 값으로 되돌리며, Gemini CLI·Qwen Code는 `telemetry`에서 아직 TokenCat 값을 가진 항목(`enabled`, `target`, `otlpEndpoint`, `otlpProtocol`, `logPrompts`)을 백업의 값으로 되돌립니다(없었으면 지우고, 비게 된 `telemetry`도 지움). 연결 후 TokenCat 항목이 바뀌도록 수정된 Gemini CLI·Qwen Code 파일은 다음 실행 때 다시 쓰지 않으며, 설정 › 실측에 건너뛰었다고 표시합니다. TokenCat 키가 TokenCat 값도 원래 값도 아닌 값으로 바뀌었거나, 원래 Codex 설정에 `[otel]` 표가 있었거나(TokenCat 키가 그 표에 섞임) 붙인 줄이 달라졌거나, 수정된 Claude Code 설정이 아래 상태 표시줄 단계 뒤에도 브리지를 가리키면(연결 기록을 남김) 어느 파일도 바꾸지 않고 해당 파일 이름을 알립니다. 어느 경우든 Claude Code `statusLine.command`가 TokenCat이 쓴 브리지 명령 그대로이면 그 항목을 먼저 되돌립니다. 브리지를 더한 직후 그대로인 파일이면 바꾸기 전 바이트를, 아니면 기록해 둔 원래 `statusLine` 객체(원래 없었으면 키를 지움)를 넣고 다른 키는 지금 그대로 둡니다. 가능하면 명령 문자열만 바꿔 서식을 유지하고, 바꾸기 직전 파일은 백업 폴더에 `claude-settings-before-statusline-restore-<시각>.json`(0600)으로 남깁니다. 그 뒤 브리지를 가리키는 곳이 없으면 브리지 스크립트와 원래 명령 파일을 지우고, 결과를 결과·오류 문장 끝에 붙입니다(`Claude Code 상태 표시줄은 원래 명령으로 되돌렸습니다.`, `TokenCat이 추가한 Claude Code 상태 표시줄은 지웠습니다.`, `상태 표시줄도 지금 설정 그대로 두었습니다.`, 되돌리지 못하면 원래 명령 파일 위치). 상태 표시줄이 브리지 명령과 다르면 그대로 두며, 다른 표기로라도 브리지를 가리키는 동안에는 스크립트를 남깁니다. 거절된 파일의 나머지 실측 설정은 백업을 보고 직접 정리하고, `settings.json`이 아직 `claude-statusline.sh`를 가리키는 동안에는 `~/Library/Application Support/TokenCat/`을 지우지 않습니다(원래 명령이 그 안에 있어, 지우면 상태 표시줄 실행이 실패합니다). 복구는 다음 클라이언트 실행부터 적용됩니다. `--disconnect-telemetry`는 거절된 경우에도 설정 값 `telemetryDisconnected`를 남겨 앱이 다시 자동 연결하지 않게 하고, `--connect-telemetry`가 이를 지웁니다. `--connect-telemetry`는 실행 중인 TokenCat 수집기가 있어야 바로 연결하며, 없으면 연결하지 않고 끝나지만 설정 값은 지워져 다음 앱 실행 때 자동으로 연결합니다.

설정 › 실측의 `연결 해제…`(확인 후)는 실행 중인 앱 안에서 `--disconnect-telemetry`와 같은 일을 메인 스레드 밖에서 합니다. 먼저 `telemetryDisconnected`를 켜고 클라이언트 설정을 복구한 뒤 재시작 안내를 지우며, 복구를 거절하면 그 탭의 경고 줄에 보입니다. 같은 줄의 `다시 연결`은 그 설정을 지우고, 수집기가 실행 중일 때의 `--connect-telemetry`처럼 바로 연결합니다.

### 구독 계정

한도 카드는 계정을 고른 뒤 창을 합칩니다. 제공사마다 진행 중인 세션이 쓰는 계정별로 한 블록을 사용률 내림차순으로 두고, 오른쪽에는 창마다 한 줄씩 5시간을 주간보다 먼저 둡니다. 제공사는 첫 계정에만 적고, 왼쪽에는 계정 이름과 출처 한 줄을 둡니다. 진행 계정에 한도가 없어도 다른 계정의 수치를 빌리지 않습니다. 진행 세션이 없으면 가장 최근 활동 세션의 계정, Claude Code·Codex CLI의 기본 계정, 계정을 알 수 없는 이전 한도 순으로 고릅니다. 가장 최근 계정에 쓸 값이 없으면 더 오래된 세션 대신 기본 계정으로 넘어갑니다.

- **Claude Code**: 세션의 설정 디렉터리 `.claude.json` → `oauthAccount`에서 계정 ID·이메일·조직 메타데이터를 읽습니다. 기본 `~/.claude` 디렉터리는 `~/.claude.json`을 쓰고, 이전 `~/.config/claude` 디렉터리에 자체 메타데이터가 없으면 그 파일로 돌아갑니다.
- **Codex**: 롤아웃 홈의 `auth.json`에서 `tokens.account_id`만 읽습니다. 계정 귀속을 위해 토큰 값을 읽거나 `id_token`을 해독하지 않습니다.
- **omp·Pi**: 제공사별 최신 `credential_pin`을 해당 세션 루트의 `agent.db` `auth_credentials` 표에 있는 OAuth 메타데이터와 대조합니다. 꺼진 자격 증명도 기존 세션을 식별하는 데 씁니다. 하위 에이전트는 자기 핀이 없으면 부모의 제공사 핀을 이어받습니다. 클론과 다른 클라이언트에는 구독 계정을 붙이지 않습니다.
- **신원과 이름**: 앞뒤 공백을 없애고 소문자로 바꾼 ID·선택적 이메일이 정확히 같을 때만 같은 계정입니다. 조직명은 표시용입니다. 이메일이 없으면 같은 ID의 알려진 계정이 정확히 하나일 때만 그 회원으로 해석합니다. 그 밖에는 같은 워크스페이스 ID를 두 회원이 공유하더라도 `(id, 이메일 없음)`을 따로 둡니다. 제공사에 알려진 계정이 둘 이상일 때만 이름을 붙이며, 이메일이 있으면 @ 앞부분(`seuput · team`), 없으면 ID 끝부분을 씁니다. 전체 이름이 같으면 구별되는 조직명이나 ID 끝부분으로 나누고 필요하면 짧은 해시도 붙입니다. 서로 다른 이름을 줄였을 때 같아지면 카드에 전체 이름을 보입니다. 도움말과 VoiceOver에는 항상 전체 이름을 남깁니다.
- **개인정보와 저장**: 계정 ID·이메일은 귀속과 이름 표시를 위해 메모리에만 두고 TokenCat 파일·로그·진단 JSON에는 쓰지 않습니다. 저장하는 Claude 한도는 정규화한 계정 키의 SHA-256 앞 16자리 16진수 해시를 키로 한 숫자 창만 담습니다. 예전 단일 Claude 값은 기본 계정으로 옮기며, 기본 계정을 모르면 계정 미확인 기록으로 남습니다.

### Claude 사용 한도와 상태 표시줄 브리지

Claude Code는 계정 사용 한도를 로그나 OTLP로 보내지 않고, 상태 표시줄 명령에 표준 입력으로 넘기는 JSON의 `rate_limits`에만 넣습니다. `five_hour`·`seven_day`는 Claude.ai 구독 계정에서 첫 응답을 받은 뒤부터 들어 있습니다. 그래서 TokenCat은 연결할 때 `~/.claude/settings.json`의 `statusLine`을 다음처럼 감쌉니다.

- `{"type": "command", "command": …}`이면 `command`만 `/bin/sh "$HOME/Library/Application Support/TokenCat/claude-statusline.sh"`로 바꾸고 `padding` 같은 다른 필드는 둡니다. 가능하면 명령 문자열만 바꿔 파일 서식도 유지합니다. 원래 명령은 같은 폴더의 `claude-statusline-command`(0600)에, 바꾼 `statusLine` 객체는 연결 기록 `telemetry-connection.json`의 `statusLine.original`에 남깁니다.
- `statusLine`이 없으면 브리지만 추가합니다. 이 브리지는 전달만 하고 아무것도 출력하지 않습니다.
- 명령이 비었거나 다른 형식이면 한도 연결만 건너뜁니다. 이미 브리지를 가리키는 명령은 경로 표기가 달라도 다시 감싸지 않으며, 한 번 감싼 뒤 사람이 바꾸거나 지운 상태 표시줄은 그대로 둡니다.
- 브리지 이전 버전(0.8.0 이하)에서 연결한 설치는 다음 실행 때 같은 백업 폴더에 바꾸기 전 파일(`claude-settings-before-statusline.json`)을 남기고 브리지만 더합니다. 원래 명령 파일이 없어졌으면 연결 기록에서 다시 만들고, 기록 없이 브리지만 가리키면(다른 Mac에서 복사한 설정 등) 상태 표시줄이 비어 보이므로 직접 고쳐야 합니다. 건너뛴 이유와 이런 안내는 설정 › 실측의 `Claude 한도` 줄과 `--connect-telemetry` 출력에 나옵니다.

브리지 스크립트(0700)는 받은 JSON을 그대로 `curl`로 `http://127.0.0.1:16493/v1/claude/status`에 보냅니다. `~/.curlrc`와 프록시를 쓰지 않고 연결 1초·전체 2초 제한으로 백그라운드에서 보내므로, TokenCat이 없거나 느려도 상태 표시줄이 기다리지 않습니다. 그다음 원래 명령을 같은 입력으로 실행해 출력과 종료 코드를 그대로 돌려줍니다. TokenCat은 두 창의 `used_percentage`(0–100)·`resets_at`·수신 시각을 남깁니다. `session_id`는 메모리에서만 써서 합치기 전에 해당 세션 계정으로 보내고, 모르는 세션은 기본 Claude 계정으로 돌아갑니다. 다른 상태 정보는 버립니다. 숫자 창은 다음 실행을 위해 UserDefaults `claudeUsageLimits`에 계정 해시 키별로 저장합니다(`defaults delete dev.seuput.TokenCat`로 지움). 같은 계정·창에서는 더 늦게 받은 값이 우선합니다. Claude Code가 상태 표시줄을 다시 그릴 때만 갱신하므로 [실시간 확인](#실시간-한도-확인)이 없으면 마지막 값과 그 나이를 보입니다. 연결 뒤에는 Claude Code가 설정을 다시 읽어야(보통 새로 실행한 뒤) 브리지를 씁니다.

Claude 데스크톱 앱의 Claude Code는 상태 표시줄을 실행하지 않습니다. TokenCat은 데스크톱 앱이 약 15분마다 쓰는 `~/Library/Application Support/Claude/plan-usage-history.json`도 읽기만 합니다. `version` 2의 마지막 `samples` 항목에서 시각과 `u.fh`·`u.sd` 사용률을 읽습니다. `org`가 있으면 기본 Claude 조직 ID와 일치해야 하며 다른 조직은 무시합니다. `org`가 없으면 기본 Claude 계정에 붙입니다. 이전 샘플·다른 형식·2MB 초과 파일은 무시하고, 크기나 수정 시각이 바뀔 때만 다시 읽습니다. 초기화 시각은 만들어 내지 않고 `N분 전 기록`만 보이며, 기록 뒤 창 길이(5시간·7일)가 지나면 초기화된 것으로 봅니다. 같은 계정의 창마다 데스크톱 기록과 브리지 값 중 더 늦은 값을 씁니다.

### omp·Pi 사용량 기록

omp·Pi는 자기 Claude·ChatGPT 로그인의 한도를 확인해 에이전트 폴더의 `agent.db` `usage_history`에 쌓습니다(`$PI_CODING_AGENT_DIR`, `~/.omp/agent`, `~/.pi/agent`; Windows는 `%USERPROFILE%\.omp\agent`·`%USERPROFILE%\.pi\agent`). TokenCat은 읽기 전용으로 열어 계정·창마다 최신 행을 읽고, 계정 ID·이메일 메타데이터는 메모리에서 귀속에 씁니다. `anthropic:5h`·`anthropic:7d`는 Claude 5시간·주간 창, `openai-codex:primary`/`secondary`는 Codex 창이 되며 길이는 `7 days`·`5 hours` 같은 이름에서 읽습니다. 모델별 주간 한도·Codex 추가 미터·다른 제공사는 건너뜁니다. DB나 WAL이 바뀔 때만 다시 조회합니다.

- **모든 계정**: 마지막으로 확인한 계정이나 Claude Code 계정뿐 아니라 모든 계정의 유효 창을 따로 둡니다. 이메일이 없으면 위의 유일 ID 해석 규칙을 따르고, 계정 ID가 없는 행은 이전 계정 미확인 데이터로 남습니다.
- **합치기**: 실시간 값이 아니라 기록입니다. 같은 계정의 창끼리만 시각을 비교해 더 최근 omp·Pi 기록이 오래된 상태 표시줄·데스크톱 값을 대신하며, Codex는 마지막 실시간 확인보다 늦은 기록이 같은 계정·초기화 창의 로그 기록과 함께 쓰입니다.
- **표시**: 경과 시간은 omp·Pi의 기록 시각 기준이며 계정의 출처 줄에 누가 기록했는지 함께 적습니다(`omp · 4분 전`). 도움말은 그 클라이언트가 직접 확인한 값이라고 알려 주고, 설정 › 실측의 `Claude 한도` 줄은 `omp 기록 · 4분 전`으로 보입니다.

### 실시간 한도 확인

설정 › 실측의 `실시간 한도 확인`(기본 켜짐, macOS·Windows)은 로그나 상태 표시줄 기록을 기다리지 않고 계정의 지금 한도를 묻습니다. 실시간 값은 위 경로의 값과 함께 쓰며, 같은 창의 더 오래된 기록보다 우선합니다. 끄면 이 요청을 보내지 않습니다.

- **Codex**: 로컬 `codex app-server`를 실행해 JSON-RPC `account/rateLimits/read`로 묻고 종료합니다. 이 실시간 값은 현재 Codex CLI 계정에만 붙습니다. 다른 Codex 계정은 해당 롤아웃 한도와 omp·Pi 기록을 씁니다. CLI가 자기 로그인으로 OpenAI와 통신하며 TokenCat은 Codex 토큰 값을 읽지 않습니다.
- **Claude**: 계정마다 그 계정의 저장된 로그인만 씁니다. 기본 홈 계정은 macOS 키체인의 `Claude Code-credentials`를 `/usr/bin/security`로 읽거나(한 번 허용을 물을 수 있고 거부해도 파일 자격 증명은 사용 가능) `~/.claude/.credentials.json`을 읽습니다. 다른 Claude Code 설정 디렉터리는 자체 `.credentials.json`을, Windows는 `%USERPROFILE%\.claude\.credentials.json`을 씁니다. omp·Pi의 `agent.db`에서 해당 계정의 켜진 Anthropic OAuth 자격 증명도 후보로 쓰며 Claude Code에서 쓰지 않는 계정도 포함합니다. 액세스 토큰·만료 시각·계정 메타데이터로 정확한 계정에 연결하고, 쓸 수 있는 후보로 `GET https://api.anthropic.com/api/oauth/usage`를 보냅니다. 토큰은 메모리에만 두고 파일·로그·프로세스 인자에 남기거나 갱신하지 않습니다. 만료됐거나 60초 안에 만료될 토큰은 건너뛰고, 401·403을 받은 토큰은 바뀔 때까지 그 계정에서 거부하며 리디렉션은 허용하지 않습니다. 쓸 토큰이 없으면 그 계정의 기록 경로를 씁니다.
- **주기**: 제공사·계정 슬롯마다 해당 계정의 모델을 쓰는 세션이 실행 중이거나 상세 화면이 열려 있으면 1분, 그 밖에는 10분마다 확인합니다. 어느 클라이언트에서 돌든 Claude 모델은 Claude로, OpenAI GPT·o 시리즈·Codex 모델은 Codex로 셉니다. 상세 화면을 열 때 마지막 확인이 15초 이상 지났으면 확인합니다. 잠자거나 화면이 꺼지면 멈춥니다. 주기·거부 토큰·실패 간격 늘리기(macOS 최대 15분, Windows 최대 30분)는 계정별로 독립적이며 제공사·계정 슬롯마다 한 번에 요청 하나만 보냅니다.
- **표시**: 2분 안의 실시간 값은 `… · 실시간`, 그보다 오래된 값은 기존처럼 `… · 5분 전 기록`으로 보입니다. 응답에 초기화 시각이 없으면 표시하지 않습니다.
- **그 밖에 보내는 것 없음**: 사용 기록·기기 정보·식별자는 보내지 않습니다.

macOS의 `TokenCat --live-limits`는 계정별 실시간 확인과 omp·Pi 기록 및 경과 시간, 이어서 상세 화면이 선택한 행을 출력합니다. 계정 ID 끝부분만 쓰며 이메일·토큰은 출력하지 않습니다.

### 세션과 상태

Codex·Claude Code 하위 에이전트도 별도로 수집하며 정확한 부모 세션 식별자(Claude Code는 공유 세션 ID, Codex는 루트 스레드 ID)로 묶습니다. 포크된 Codex 로그가 부모의 세션 메타데이터를 다시 기록해도 파일 이름의 스레드 ID로 자기 신원을 유지하며, 다시 기록된 부모의 사용 한도·압축 기록은 제외합니다.

진행 중 표시는 열린 턴의 마지막 로그 기록 이후 허용 시간 안에 있을 때입니다. 모델 응답 대기는 10분, Claude Code 도구 실행은 15분, Codex 도구 실행은 120초이며 모든 종류의 로그 기록이 반영됩니다. 허용 시간이 지나면 `로그 대기`로, 마지막 기록 후 30분이 지나면 `종료 기록 없음`으로 바뀝니다. Claude Code가 질문(AskUserQuestion)이나 계획 승인(ExitPlanMode)을 기다리면 `입력 필요`이며 `로그 대기`로 바뀌지 않고 24시간 동안 기록이 없으면 `종료 기록 없음`이 됩니다. Codex Plan 모드의 질문(`request_user_input`)도 같은 규칙으로 `입력 필요`이며, 비동기 `request_user_input_async`는 일반 도구로 취급합니다. 권한 확인 요청은 로그에 남지 않아 표시하지 않습니다. OS 프로세스 생존 여부를 뜻하지 않으며, 파일 수정 시각은 활동 시각으로 사용하지 않고 변경 감지에만 사용합니다.

실행 중인 도구는 이름만으로 명령 실행·파일 작업·웹 조회·하위 에이전트·MCP·질문·기타로 구분합니다. 도구 입력은 읽지 않으며 원래 도구 이름은 도움말에만 표시합니다. Claude Code API 재시도 기록에서는 재시도 횟수·최대 횟수·대기 시간·네트워크 끊김 여부만 읽고(`재시도 2/10 · 4초 후`), 오류 메시지는 저장하지 않으며 다음 응답이 오거나 턴이 끝나면 해제합니다.

세션 행은 클라이언트가 붙인 세션 제목이 있으면 그 제목으로 표시하고 프로젝트 폴더는 옆에 남깁니다(진행 중 행은 둘째 줄 맨 앞, 조용한 행은 제목 뒤이며 제목이 먼저 잘립니다). 도움말·VoiceOver·`지금 속도`는 둘 다 말합니다. 클라이언트가 만든 제목이나 사용자가 바꾼 이름만 최신 것으로 읽고, 이름을 바꾸거나 다시 만들면 바로 따라갑니다. Claude Code는 `custom-title`(`/rename`)이 `ai-title`보다, 그것이 예전 `summary` 기록보다 앞서고, Codex는 `~/.codex/session_index.jsonl`의 스레드 이름, OpenCode·Kilo Code·MiMo Code는 `New session - <시각>` 자리표시를 대신한 `session.title`(MiMo의 대체 제목은 버림), omp는 제목 칸과 `title_change` 기록, Pi는 `session_info` 이름, Gemini CLI는 생성된 `summary`, Qwen Code는 `custom_title` 기록, Copilot CLI는 `workspace.yaml`의 `name`(없으면 생성된 `summary`), Amp는 스레드 `title`, Droid는 생성되거나 바뀐 `session_start` 제목, Cursor는 생성된 대화 이름, Grok은 생성되거나 `/rename`한 제목, Hermes는 모델이나 사용자가 정한 제목, OpenClaw는 label이나 생성된 표시 이름, Goose는 생성되거나 레시피가 정했거나 바뀐 이름, Kimi Code는 생성되거나 바꾼 제목입니다. Cline·Roo Code·Kilo Code 확장·Zoo Code·IBM Bob은 작업 제목이 첫 프롬프트라 제목이 없고, Kimi CLI 세션, 제목이 아직 첫 메시지인 Droid 세션, Hermes의 `derived` 제목, 첫 프롬프트를 옮긴 Grok 제목, 이름을 바꾸기 전의 CLI·ACP 에이전트 제공자 Goose 세션도 마찬가지입니다. 제목은 제어 문자와 보이지 않는 서식 문자를 빼고 한 줄 80자로 자르며, 메모리에만 두고 디스크에 쓰거나 보내지 않습니다. `--diagnose`는 다른 세션 메타데이터와 함께 출력합니다.

Codex 사용 한도는 로그에 기록된 사용률·주기·초기화 시각을 기록 시각과 함께 씁니다. Claude 사용 한도는 로그가 아니라 [상태 표시줄 브리지](#claude-사용-한도와-상태-표시줄-브리지)로 받은 값을 받은 시각과 함께, Claude 데스크톱 앱 사용량 기록은 그 기록 시각과 함께 씁니다. 두 클라이언트 모두 [실시간 확인](#실시간-한도-확인) 값은 받은 시각과 함께, [omp·Pi 사용량 기록](#omppi-사용량-기록)은 그 기록 시각과 함께 씁니다. 컨텍스트는 Codex가 마지막 응답의 입력 토큰과 같은 기록의 모델 컨텍스트 창을, Claude Code가 입력·캐시 토큰 합계를 씁니다. Claude Code 창 크기는 모델 이름으로 추정하지 않으며, 압축은 완료 기록 시각만 표시합니다.

토큰 증가는 로그가 기록한 시점에만 반영하며 중복 사용량은 다시 더하지 않습니다. Codex는 응답 직후 남기는 `token_usage_record`(응답별·턴 누적 출력)를 사용하므로 도구 실행이 끝나기를 기다리지 않습니다. `response_id`로 중복을 제거하며, 이 기록이 없는 이전 버전 로그에서만 `token_count`를 사용합니다. Claude Code는 메시지가 끝날 때 기록하므로 생성 중인 토큰은 메시지 완료 후 반영됩니다. Claude Code 로그가 길면 최대 16MB 범위에서 열린 턴의 입력을 역방향으로 찾아 그 지점부터 읽습니다. 현재 턴 전체 구간을 확인할 수 없을 때만 누적량을 `—`로 표시합니다. 턴 종료는 Claude Code의 종료 기록, 하위 에이전트의 턴 종료 도구 결과, 도구 호출 없는 최종 응답, API 오류·중단 기록으로 확인합니다. 최종 응답 뒤에 기록이 이어지면(Stop 훅 등) 같은 턴을 이어갑니다. 완료·중단을 확인하면 현재 턴 경과시간과 누적량을 지웁니다. 세션 복원으로 다시 기록된 이전 기록은 다시 반영하지 않습니다.

### 수집 범위와 갱신

Claude Code의 터미널·데스크톱 실행 경로를 수집합니다. Claude 웹·일반 데스크톱 채팅은 Claude Code와 다른 경로이므로 수집 대상이 아닙니다. 최근 로그 파일을 Codex 32개, Claude Code 메인 32개·하위 에이전트 32개(1시간 안에 바뀐 하위 에이전트 로그는 64개)까지 읽으며 이후 추가된 부분만 수집합니다. 진행 중이거나 1시간 이내 기록이 있는 세션은 더 새로운 파일이 많아도 계속 추적합니다(추적 파일 합계 최대 256개). 로그 디렉터리의 파일 변경 이벤트(FSEvents)로 기록 즉시 다시 읽으며(최대 초당 4회), 1초 주기 확인과 60초 주기 새 파일 확인을 함께 유지하고, 아직 추적하지 않던 로그에 기록이 생기면 바로 엽니다. 1MB를 넘는 한 줄은 내용을 읽지 않고 앞부분의 도구 호출 식별자만 확인합니다. 긴 Codex 로그는 최대 16MB 범위의 모델·턴 메타데이터를 역방향으로 확인합니다. 누락된 토큰 구간은 재구성하지 않습니다. 시스템·로그 수집과 로컬 실측은 각각 독립된 백그라운드 큐에서 처리하며, 메모리 압력은 커널의 압력 단계(정상·경고·위험)를 읽습니다.

TokenCat 자체는 모델을 호출하거나 계정에 로그인하지 않으며(실시간 한도 확인은 Codex·Claude Code 또는 omp·Pi에 저장된 로그인을 씁니다), 로그인 항목 등록과 알림은 설정에서 직접 켠 경우에만 합니다. 인터넷 접속은 [업데이트](#업데이트와-배포)의 최신 버전 확인, 사용자가 누른 내려받기, `실시간 한도 확인`이 켜져 있을 때의 [사용 한도 확인](#실시간-한도-확인)(Codex CLI를 거친 OpenAI, `api.anthropic.com`)뿐이고, 수집기를 포함한 나머지 통신은 모두 루프백(`127.0.0.1`)에서만 일어납니다.

실제 환경에서는 Codex 0.160.0의 서버 TBT 수신과 네이티브 화면 표시를 확인했습니다. Claude Code에서도 인증된 실제 요청의 출력 토큰·성공 요청 시간·첫 토큰 시간을 수신하고, 동일한 세션·요청 식별자의 로컬 로그와 대조했습니다. 예를 들어 `claude-opus-5-5`의 200 출력 토큰 / 4,532 ms는 요청 처리율 44.1 tok/s이며, 순수 생성 속도를 뜻하지 않습니다. 실측 데이터가 없는 경우에는 숫자를 표시하지 않습니다.

## 업데이트와 배포

배포는 GitHub Release로 합니다. `v<CFBundleShortVersionString>` 태그(예: `v0.9.0`)의 최신 릴리스에 `TokenCat-macOS.zip`을 올리며, zip 맨 위에 `TokenCat.app`이 있습니다(0.18.2부터. 0.18.1 이하 Mac 앱은 `TokenCat.zip`만 찾으므로 같은 파일을 그 이름으로도 올립니다). 0.11.0부터는 같은 릴리스에 `TokenCat-Windows.zip`도 함께 올립니다([Windows](#windows)). 앱은 arm64·x86_64 universal 바이너리(최소 macOS 13)이고 ad-hoc 서명만 하며 Developer ID 서명·공증은 하지 않습니다.

**확인**: `GET https://api.github.com/repos/SeuPut0705/TokenCat/releases/latest` 한 가지만 요청합니다(`Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`, `User-Agent: TokenCat/<버전>`, 사용자 언어 목록 대신 고정한 `Accept-Language: en`; macOS가 `Host`·`Accept-Encoding: gzip, deflate`·`Connection`을 덧붙입니다). 설치 파일 내려받기도 같은 `User-Agent`·`Accept-Language`만 보냅니다. 응답에서는 `tag_name`, `html_url`, `draft`, `prerelease`와 `TokenCat-macOS.zip` 자산(이 자산이 없는 예전 릴리스는 `TokenCat.zip`)의 `browser_download_url`·`size`·`digest`(`sha256:<hex>`)만 읽고, 식별자나 사용 정보는 보내지 않습니다. `새 버전 자동 확인`(기본 켜짐)이 켜져 있으면 실행 약 5초 뒤, 15분마다(타이머 허용 오차 포함), 잠자기에서 깨고 약 15초 뒤, 마지막 확인이 5분 넘게 지난 상태에서 상세 화면을 열 때 확인하며, 요청은 한 번에 하나만 보냅니다. 끄면 `지금 확인`을 누를 때만 묻습니다.

**요청 한도**: 인증 없는 GitHub API는 IP당 시간당 60회이고 304 응답도 셉니다. 그래서 마지막 응답의 ETag와 릴리스 정보를 저장해 `If-None-Match`로 묻고, 403·429에 `X-RateLimit-Remaining: 0`·`X-RateLimit-Reset`·`Retry-After`가 오면 그 시각까지 쉽니다. 초기화 시각은 응답의 `Date`를 기준으로 재므로 Mac 시계가 틀려도 늘어나지 않으며, 쉬는 시간은 1분에서 1시간 사이로 자릅니다. 네트워크 오류는 1·2·4·8분으로 간격을 늘려 다시 시도하며 최대 15분이고, 잠자기에서 깬 뒤의 확인도 이 간격을 지킵니다. `지금 확인`은 오류 간격은 건너뛰지만 요청 한도로 쉬는 시간은 지킵니다. 쉬는 동안 `업데이트`를 누르면 이미 받아 둔 릴리스 정보로 내려받으며, 크기와 SHA-256 확인은 그대로 합니다.

**설치**: 사용자가 `업데이트`(상세 화면 아래쪽, 설정 › 정보)나 빠른 메뉴의 `업데이트 1.0.0 설치…`를 누를 때만 합니다. `TokenCat-macOS.zip`을 내려받아 `digest`의 SHA-256과 대조하고, 맞을 때만 앱을 바꾼 뒤 다시 실행합니다. 다시 열리면 `1.0.0으로 업데이트했습니다`를 한 번 보입니다. 상세 화면의 알림 줄을 닫으면 그 버전만 숨기고, `새 버전 알림`을 켜 두면 새 버전마다 소리 없는 시스템 알림을 한 번 보냅니다(더 새 버전은 이전 알림을 대신하고, 설치를 시작하거나 업데이트를 마치면 지웁니다). `설치 중…` 단계에서 종료하면 그 단계(수 초, 최대 60초)를 마친 뒤 종료하고, 이전 앱 사본만 지우지 못한 경우는 설치된 것으로 봅니다. 설정 값(UserDefaults)과 실측 백업은 앱 밖에 있어 교체 뒤에도 남습니다.

**푸시 때 검사**: main 푸시와 PR이 `Sources/`, `Assets/`, `build.sh`, `Package.swift`를 건드리면 `macos-26`에서 [`.github/workflows/macos.yml`](../.github/workflows/macos.yml)이 `./build.sh`, `--self-test`, `--telemetry-lifecycle-checks`를 실행합니다.

**릴리스 만들기**: `build.sh`의 버전을 올려 main에 푸시하면 [`.github/workflows/release.yml`](../.github/workflows/release.yml)이 실행됩니다. `build.sh`에서 버전과 빌드 번호를 읽어 `v<버전>` 태그가 이미 있으면 아무것도 하지 않습니다. 없으면 macOS 26 러너(`macos-26`, 이미지 기본 Xcode)에서 도구 버전을 출력하고 `./build.sh`, `--self-test`(러너에 Rosetta가 있으면 x86_64로도), `--telemetry-lifecycle-checks`, `lipo -archs`의 arm64·x86_64 확인, Info.plist 버전과 태그 대조, `codesign --verify --deep --strict`를 거쳐 `ditto -c -k --sequesterRsrc --keepParent dist/TokenCat.app TokenCat-macOS.zip`으로 묶어 `TokenCat.zip`으로도 복사하고 SHA-256을 출력합니다. 버전 확인 단계는 새 버전이 현재 최신 릴리스보다 높지 않거나 [`CHANGELOG.md`](../CHANGELOG.md)에 `## <버전>` 항목이 없으면 멈춥니다. 영어 다음 한국어로 릴리스 노트(소개 한 줄, `CHANGELOG.md`의 해당 버전 항목, 이전 태그와의 비교 링크, SHA-256을 먼저 확인하는 터미널 설치·Gatekeeper 안내, 처음 실행 때의 설정 자동 연결·상태 표시줄 감싸기와 해제 명령, SHA-256)를 만들어 `gh release create --draft`로 태그 없는 초안을 만들고(이전 실행이 남긴 같은 태그의 초안은 먼저 지움), 초안 자산의 `digest`가 zip의 SHA-256과 같을 때만 최신 릴리스로 게시합니다. 게시 뒤 `/releases/latest`가 새 태그와 같은 `digest`를 돌려주는지 몇 차례 다시 읽어 확인합니다. 실행은 동시성 그룹 `release` 하나로 묶여 진행 중인 릴리스를 취소하지 않습니다. 다만 GitHub는 기다리는 실행을 가장 새 것 하나만 남기므로, 릴리스 중에 버전을 두 번 이상 올려 푸시하면 중간 버전은 건너뛰고 가장 새 버전만 게시합니다.

**Gatekeeper**: 공증하지 않은 앱이라 `spctl -a -vv -t exec`는 격리 여부와 관계없이 `rejected`로 평가하고, `syspolicy_check distribution`은 `Adhoc Signed App`(경고)과 `Notary Ticket Missing`(치명)을 보고합니다(macOS 27.0.1에서 확인). macOS는 이 평가를 격리 속성(`com.apple.quarantine`)이 붙은 앱을 처음 열 때 적용하므로, 브라우저로 받은 사본은 한 번 허용해야 하고 `curl`로 받아 `ditto -x -k`로 푼 사본은 격리 속성이 없어 바로 열립니다.

## Windows

Windows 버전은 [`windows/`](../windows)에 있습니다(C# .NET 10, WPF와 WinForms `NotifyIcon`, 외부 패키지 없음). Mac 앱의 UI가 아니라 규칙을 옮겼으며, 설계와 Mac 대비 제외 항목, PC 점검 목록은 [`windows/DESIGN.md`](../windows/DESIGN.md)에 있습니다. 설치와 사용자 입장에서 다른 점은 [README › Windows](../README.ko.md#windows)에 있습니다.

- **프로젝트**(`windows/TokenCat.Windows.slnx`): `TokenCat.Core`(`net10.0`, Windows API 없음)가 모든 규칙과 검사를 담습니다. 로그 추적, `127.0.0.1:16493` 루프백 수집기, 클라이언트 설정과 PowerShell 상태 표시줄 브리지, 표시 규칙, 캐릭터 동작, 업데이트가 여기에 있습니다. `TokenCat.App`(`net10.0-windows`)은 알림 영역 아이콘, 플라이아웃 상세 화면, 설정 창, 시스템 지표, 로그인 항목(`HKCU\…\Run`), 명령줄 옵션만 맡는 얇은 셸입니다. `TokenCat.Checks`는 Core 검사를 돌리는 콘솔 실행기입니다.
- **Mac과 공유**: 버전은 `Directory.Build.props`가 `build.sh`에서 읽고, 스프라이트와 매니페스트는 `Assets/`에서 그대로 포함하므로 두 앱의 버전과 그림이 하나입니다. 설정 값은 Mac의 UserDefaults 키 이름 그대로 `%LOCALAPPDATA%\TokenCat\settings.json`에 둡니다.
- **클라이언트 폴더**: 같은 제공사 목록을 Windows 위치로 씁니다. 홈 폴더를 쓰는 클라이언트는 `%USERPROFILE%`(`.codex`, `.claude`, `.cursor`, `.grok`, `.openclaw`, `.kimi-code`, `.kimi` 등)이고, `CODEX_HOME`·`CLAUDE_CONFIG_DIR`과 위의 다른 변수도 같은 방식으로 위치를 바꿉니다. OpenCode 계열과 Amp는 `%USERPROFILE%\.local\share`(또는 `XDG_DATA_HOME`)입니다. 그 밖에는 Cline 계열 작업이 모든 `%APPDATA%\<에디터>\User\globalStorage\<확장>\tasks`, Qoder가 `%APPDATA%\Qoder\SharedClientCache\cli\projects`, Cursor 데이터베이스가 `%APPDATA%\Cursor\User\globalStorage\state.vscdb`, Hermes가 `%LOCALAPPDATA%\hermes`(또는 `HERMES_HOME`), Goose가 `%APPDATA%\Block\goose\data\sessions`(또는 `GOOSE_PATH_ROOT`), Kimi Work가 `%APPDATA%\kimi-desktop\daimon-share\daimon\runtime\kimi-code\home\sessions`입니다. Gemini CLI의 macOS 샌드박스 폴더와 omp의 `XDG_DATA_HOME` 구성은 Windows에 없습니다.
- **화면 위젯**(0.12.0): 메뉴 막대 항목을 같은 규칙(항목, 고정 칸 너비, 상태 표시, 글자 톤)으로 작은 테두리 없는 최상위 창에 그립니다. 이 창은 포커스를 가져가지 않고 작업 표시줄과 Alt+Tab에도 나오지 않습니다. 100%에서는 어떤 디스플레이 배율에서도 1pt가 정수 픽셀이라 캐릭터가 흐려지지 않고, 더 큰 크기(300%까지, `widgetScale`)에서도 정수 픽셀이면 선명하게, 그 사이 크기는 부드럽게 그립니다. 알림 영역 애니메이션의 프레임 타이머를 함께 쓰고, 1초 갱신마다 전체 화면 앱(`SHQueryUserNotificationState`)을 확인하며, 모니터 구성마다 위치를 하나씩 기억합니다(`widgetPositions`). 크기가 바뀌어도 가까운 화면 가장자리는 그대로 둡니다. 설정 › 위젯은 Mac의 메뉴 막대 탭과 같고(`showWidget`, `statusBarLayout`, `metricOrder`, `visibleMetrics`) 크기가 더 있으며, 크기는 우클릭 메뉴나 Ctrl+마우스 휠로도 바꿉니다. 위젯의 캐릭터 표시(`showRunner`)는 Mac처럼 그 항목 목록 맨 위의 `캐릭터` 체크 상자입니다.
- **검사 동등성**: Core 검사 묶음은 Swift 검사를 실패 설명 문구까지 1:1로 옮겼고 Mac처럼 한국어로 실행하므로, 어긋난 곳을 한 번의 검색으로 두 코드에서 찾을 수 있습니다. Core 빌드와 검사는 macOS에서도 실행됩니다(`dotnet build windows/TokenCat.Windows.slnx -c Release`, `dotnet run --project windows/TokenCat.Checks -c Release`). Windows에서는 `TokenCat.exe --self-test`가 App 검사(포함된 그림, 아이콘 핸들 누수, 테마 대비)를 더합니다.
- **CI**([`windows.yml`](../.github/workflows/windows.yml)): main 푸시와 PR이 `windows/`, `Assets/`, `build.sh`를 건드리면 `windows-latest` 러너에서 경고를 오류로 빌드한 뒤 단일 파일 `TokenCat.exe`(win-x64, self-contained)를 게시하고, ProductVersion이 `build.sh` 버전과 같은지 확인합니다. 이어서 `--self-test`(App 검사와 Core 검사), `--telemetry-lifecycle-checks`(실제 루프백, Git Bash와 PowerShell로 실행한 브리지 명령), 방금 묶은 zip에 대한 `--update-selftest`, `--snapshot`을 실행하고 zip과 스냅숏을 아티팩트로 올립니다.
- **릴리스**([`release.yml`](../.github/workflows/release.yml)): `windows-latest`의 `windows` 작업이 빌드·`--self-test`·버전 확인을 반복하고 `TokenCat-Windows.zip`(`TokenCat.exe`와 `LICENSE`를 평평하게)을 묶어 `--update-selftest`, `--telemetry-lifecycle-checks`, `--snapshot`을 거친 뒤 Mac 릴리스 작업에 넘깁니다. Mac 작업은 SHA-256을 확인해 `TokenCat-macOS.zip`·`TokenCat.zip`과 같은 초안에 붙이고, 모든 자산의 `digest`가 맞을 때만 게시하며, `/releases/latest`에서 자산들을 다시 읽어 확인합니다. 릴리스 노트에는 영어·한국어 Windows 설치 안내가 들어갑니다. exe는 Windows에서 빌드해야 합니다. SDK가 업데이트에서 태그와 비교하는 버전 리소스를 Windows에서만 쓰기 때문이며, Windows 빌드가 실패하면 릴리스 전체가 멈춥니다.
- **업데이트**: 같은 `/releases/latest`를 요청하고, Windows 앱은 `TokenCat-Windows.zip`만 설치합니다. 크기와 SHA-256을 확인하고, zip에는 `TokenCat.exe`와 `LICENSE`만 허용하며, 새 exe의 ProductVersion을 릴리스와 대조한 뒤 실행 중인 `TokenCat.exe`를 `TokenCat.exe.old`로 이름을 바꾸고 새 파일을 넣어 `--after-update`로 다시 실행합니다. Mac 앱은 `TokenCat-macOS.zip`을 찾습니다(0.18.1 이하는 `TokenCat.zip`).
- **CI로 확인하지 못하는 것**: 배율별 알림 영역 아이콘, SmartScreen과 스마트 앱 컨트롤, IDE나 데스크톱 앱에서의 브리지, 실제 두 릴리스 사이의 앱 내 업데이트는 PC 점검 목록(DESIGN.md §12)에 있습니다.

## 검증 명령

```sh
dist/TokenCat.app/Contents/MacOS/TokenCat --self-test
dist/TokenCat.app/Contents/MacOS/TokenCat --diagnose
dist/TokenCat.app/Contents/MacOS/TokenCat --connect-telemetry
dist/TokenCat.app/Contents/MacOS/TokenCat --telemetry-readings
dist/TokenCat.app/Contents/MacOS/TokenCat --disconnect-telemetry
dist/TokenCat.app/Contents/MacOS/TokenCat --live-check
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot work/dashboard.png
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot work/dashboard-light.png --light
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot-fixtures work/fixtures
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot-menubar work/menubar.png
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot-menubar work/menubar-states.png --fixtures
dist/TokenCat.app/Contents/MacOS/TokenCat --snapshot-settings work/settings.png --pane all
dist/TokenCat.app/Contents/MacOS/TokenCat --telemetry-lifecycle-checks
dist/TokenCat.app/Contents/MacOS/TokenCat --notification-status
dist/TokenCat.app/Contents/MacOS/TokenCat --update-check
dist/TokenCat.app/Contents/MacOS/TokenCat --live-limits
```

`--diagnose`는 시스템 수치·토큰 및 실측 메타데이터만 출력합니다(프로젝트 전체 경로와 세션 제목 포함, 이 Mac에서만 확인용). `--telemetry-readings`는 실행 중인 TokenCat 수집기의 실측 메타데이터를 확인합니다. `--snapshot`은 실제 로컬 지표로 상세 패널 이미지를 저장합니다. `--snapshot-fixtures`는 합성 데이터로 상세 화면 상태(입력 필요·재시도·도구 범주·로그 대기·조용함·컨텍스트·하위 세션·펼친 목록·행 상세·키보드 선택·빈 화면·로딩·실측 경고·대비 증가·Claude Code만 있는 화면·업데이트 줄의 새 버전·내려받는 중·실패)와 부품 시트(첫 실행 결과 다섯 가지, 실시간 확인과 omp 기록을 포함한 Codex 일곱·Claude 넷의 한도 행) 이미지 23장을 다크·라이트로 저장하며 로컬 로그·수집기·호스트 정보를 읽지 않고, 세션 제목도 지어낸 것입니다. `--snapshot-menubar <png> [--light] [--inline|--minimal] [--highlighted] [--fixtures] [--no-runner] [--character cat|dog|hamster|penguin|robot]`는 같은 네이티브 렌더러로 메뉴 막대 미리보기를 저장합니다. `--fixtures`는 라이트·다크와 열림 상태 네 열을 모두 그리므로 `--light`·`--highlighted`는 실데이터 미리보기에만 적용되며, 마지막 네 행은 평균 속도 항목을 켭니다(실측 클라이언트 하나·둘·넷, 없음). `--snapshot-settings <png> [--light] [--pane general|menubar|cat|telemetry|about|all] [--character cat|dog|hamster|penguin|robot] [--fixtures [--update-failure network|translocated|not-writable|no-digest|invalid-bundle] [--setup-note unknown|skipped|recreated] [--login requires-approval|enabled] [--notifications denied|authorized]]`는 설정 창 탭을 화면 밖에서 렌더하고(`--notifications denied`는 알림 선택도 모두 켜 가장 긴 상태를 만듭니다) 탭마다 높이를 보고합니다(600pt를 넘으면 표시). `--telemetry-lifecycle-checks [port]`는 실제 루프백 포트로 수집기 시작·포트 점유 구분·재시도·`지금 다시 시도`를 검사하므로 기본 `--self-test`와 분리돼 있습니다. `--notification-status`는 알림 권한 상태를 묻지 않고 읽기만 합니다. `--update-check`는 최신 릴리스를 한 번 GET으로 읽어 현재 버전과의 비교 결과를 출력하며, 내려받거나 설치하지 않고 화면도 열지 않습니다. `--live-limits`는 제공사마다 [실시간 한도 확인](#실시간-한도-확인)을 한 번 하고(그래서 Codex CLI를 거쳐 OpenAI에, 그리고 Anthropic에 접속합니다) 숫자만 출력하며 토큰은 출력하지 않습니다. 첫 CPU·네트워크 샘플은 이전 카운터가 없으므로 미측정이며 두 번째 샘플부터 표시됩니다. 어느 명령에든 `--language ko`나 `--language en`을 붙여 출력 언어를 고를 수 있습니다.

`--fixtures`와 함께 쓰면 `--snapshot-settings`는 `--collector listening`(포트 충돌 대신 정상 수집기), `--telemetry-disconnected`(`연결 해제…` 뒤의 실측 탭), `--layout minimal|compact|inline`(그 표시 방식의 메뉴 막대 탭, 최소에서는 항목 줄이 흐림)도 받습니다.

`--self-test`는 로그의 중복·부분 기록·시간 경계·재개된 세션·다중 세션 분리·모델 변경·하위 에이전트 경로·턴 종료·입력 필요·재시도·한도·컨텍스트 등을 검증하고, 러너 매니페스트 v3·자세별 프레임 수·타이밍·효과 레이어·픽셀 머리·0/255 알파, OTLP 파싱·식별자 연결·속도 산출, Claude 상태 표시줄 JSON과 Claude 데스크톱 앱 사용량 기록의 한도 해석, 표시 상태·그룹·`지금 속도`와 속도 칸 규칙·메뉴 막대 폭·설정 이전, 설정 보존·백업·복구(수정된 파일은 TokenCat 항목만)·충돌·부분 저장 실패와 상태 표시줄 브리지(감싸기·원래 명령 파일·이전 연결에 더하기·상태 표시줄만 복구), 업데이트(버전 비교·릴리스 해석·digest·요청 한도와 재시도 간격·설치 조건, 이 앱 사본으로 압축 해제·번들 검증·교체), 언어 결정과 영어 문구·시간 형식을 네트워크 없이 확인합니다. 검사는 한국어를 기준으로 돌고 영어 문구는 필요한 곳에서 언어를 바꿔 확인하므로 `--language`와 관계없습니다.

`--live-check`는 자동 갱신 주기로 실제 시스템과 로컬 로그를 약 6초간 수집합니다. 갱신 간격·중복 시작 방지·종료 후 갱신 차단을 JSON으로 출력하며 실패하면 종료 코드 1을 반환합니다. 모델을 호출하지 않습니다.

빌드는 ad-hoc 서명된 universal 앱입니다. App Store 배포·Developer ID 서명·공증은 포함하지 않으며, 업데이트는 확인만 자동이고 설치는 사용자가 누를 때만 합니다([업데이트와 배포](#업데이트와-배포)).

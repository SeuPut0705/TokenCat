# TokenCat 앱 아이콘 v2

- 생성 방식: 타일·16 · 32 px 머리·합성·목걸이 재색칠은 `Assets/Generator/IconArt.swift`가 결정적으로 그린다. 이 v2 합성 단계는 이미지 생성 서비스·네트워크를 쓰지 않는다. 가운데 마크는 기존 `app-mark-v1.png`(내장 image_gen 원본, `app-mark-v1.prompt.md`)에서 목걸이 색만 팔레트로 바꿔 쓴다. 색은 `Assets/Generator/Palette.swift`가 유일한 출처다(`runner-v2.md` 팔레트 표).
- 도구: Swift 6.4 `swiftc`, CoreGraphics(타일·그라디언트), ImageIO(PNG 읽기·쓰기). 앱 번들의 `.iconset`과 `.icns`는 `build.sh`가 `sips`와 `iconutil`로 만든다.
- 명령(저장소 루트):

  ```sh
  mkdir -p work && swiftc -O Assets/Generator/*.swift -o work/asset-generator && work/asset-generator icon
  ./build.sh && work/asset-generator previews system   # work/app-icon-v2-preview.png, work/app-icon-v3-preview.png, work/app-icon-v2-system-small.png
  ```

  아래 bytes·SHA-256은 macOS 27.0.1·Swift 6.4에서 두 번 생성해 같음을 확인한 값이다. 타일은 CoreGraphics 안티앨리어싱을, 파일은 ImageIO PNG 인코더를 거치므로 다른 OS에서는 아이콘 바이트(타일 가장자리 픽셀 포함)가 달라질 수 있다.
- 입력: `Assets/app-mark-v1.png`(SHA-256 `4350d73557050070da2caf589a3b18a6ebcb1e74bc223dc3c2d9ba6a10e20538`). 마크 파일은 수정하지 않는다. 마크는 아이콘 합성 입력일 뿐 앱 번들에는 넣지 않는다. 앱은 `Runner.headImage`의 픽셀 머리를 그린다.

## 구성

- 1024 캔버스에 824 타일(여백 100 px). 타일은 연속 곡률 슈퍼타원(n = 5)으로, 대각선 지점이 반지름 185 px 둥근 사각형과 맞는다.
- 배경: 왼쪽 위 `#5361D6`(차분한 인디고 코발트) → `#3B4787` → 오른쪽 아래 `#283246`(슬레이트) 선형 그라디언트. 위쪽 흰색 18% 광원, 안쪽 테두리는 위가 밝고 아래가 어두움. 타일 밖은 완전 투명(바깥 그림자 없음).
- 제공사 브랜드 팔레트(검정·흰색만, 클레이·크림)를 쓰지 않는다.
- 고양이: app-mark-v1을 알파 경계로 잘라 타일 폭의 68%로 축소해 중앙보다 8 px 아래에 둠. 부드러운 접지 그림자(아래 14 px, 흐림 30, 남색 43%).
- 목걸이 재색칠(B-1, v3 결정 전 임시): 마크의 목걸이 영역(마크 1254 px 격자의 1030–1170행)에서 색상각 205–240°·채도 0.5 초과 픽셀을 팔레트 `C #3A4FE0`로, 태그 원(중심 626, 1092, 반지름 46) 안은 `T #9DABFF`로 바꾼다. 픽셀별 알파와 상대 밝기(원래 파랑 `#155AFC` 대비)는 유지한다. 1024 결과에서 이전 v2와 다른 픽셀은 4963개이고 모두 목걸이 사각형(x 398–617, y 719–791) 안에 있다. 흰 하이라이트는 그대로다.
- 16 · 32 px: 메뉴 막대 고양이와 같은 픽셀 머리(B-2). `RunnerArt.head`(10 × 9, 목걸이 포함) + 1 px K 외곽선 = 12 × 11. 손으로 그린 `head16`·`head32`는 삭제했다.
  - 16 px: 머리를 (2, 3)에 1:1로 그린다. 세로 1 × 2 눈, 귀 안쪽 그늘, 목걸이와 태그.
  - 32 px: 같은 머리를 2배 최근접 확대(24 × 22)해 (4, 5)에 그린다.
  - 타일은 여백 없이 꽉 채운다. macOS 27에서 16·32 px 이미지에 1024 기준 비례 여백을 두면 회색 판 안에 갇혀 표시되었고, 꽉 채운 타일은 시스템이 마스크와 그림자를 입혀 큰 크기와 같은 모양으로 보여 주었다.

## 결정: macOS 13–15의 16 · 32 px은 알려진 절충

- `.icns` 하나를 모든 OS가 쓰므로 16 · 32 px 여백은 한쪽에만 맞출 수 있다. macOS 26 이상(이 Mac의 macOS 27에서 확인)에 맞춰 꽉 채운 타일을 유지한다.
- macOS 13–15는 작은 크기에 마스크를 씌우지 않으므로 Finder 목록·Spotlight·로그인 항목에서 16 · 32 px 아이콘이 다른 앱의 약 13 px 타일보다 약 23% 크고 그림자 없는 사각형으로 보일 가능성이 높다. 13–15 실기기에서는 확인하지 않았다. 64 px 이상은 1024 기준 여백을 그대로 쓰므로 영향이 없다.
- Icon Composer `.icon` → `actool` Assets.car(`CFBundleIconName`, 26 이상) + 여백 있는 `.icns`(13–15) 경로는 택하지 않았다. 빌드에 Xcode 26 이상의 `actool`이 필요해지거나 컴파일된 Assets.car 바이너리를 저장소에 둬야 하고, `.icon`은 작은 크기를 레이어에서 시스템이 그리므로 스프라이트에서 가져온 16 · 32 px 픽셀 머리를 26 이상에서 쓸 수 없으며, 13–15 결과도 이 Mac에서 확인할 수 없다. 13–15 사용자의 표시 문제가 보고되면 이 경로로 전환한다(이 Mac에는 Xcode 27 `actool`과 Icon Composer가 있어 시험 가능).

## 벡터 마스터 v3 미리보기 (B-4, 출시하지 않음)

- `IconArt.masterV3(size:)`가 1024 격자(y 아래 방향)의 경로를 각 크기에서 직접 렌더한다. 64–512 px도 `sips` 축소가 아니다. `build.sh`는 B-5 결정 전까지 v2를 그대로 쓴다.
- 같은 타일과 접지 그림자, 슈퍼타원 머리(n = 2.6, 552 × 450, 중심 512, 585), 바깥으로 기운 둥근 삼각형 귀(꼭짓점 284, 214 / 740, 214, 모서리 반지름 30, 귀 안쪽 S는 34 안쪽), K 외곽선 22(채움 바깥), 세로 타원 눈 60 × 88(중심 418·606, 594)과 흰 하이라이트 지름 22, 코 44 × 30, 목걸이 C 띠 256 × 34 + K 14, 태그 T 지름 56 + K 12.
- 눈썹·줄무늬·수염 없음. 입(ω, 반지름 24, 선 14)은 128 px 이상에서만. 모든 선은 2 px 아래로 내려가지 않는다.
- CBM-10의 수치(600 × 500, n = 3.2 머리와 y 480 귀 밑변)는 귀가 머리 뒤에 거의 가려 약 60 px 혹만 남아서, 머리를 줄이고 귀를 키웠다.
- `work/app-icon-v3-preview.png`: 밝은·어두운 배경마다 v2(출시본: 16 · 32는 픽셀 머리, 64–512는 1024 고품질 축소)와 v3 행을 16–512 실제 크기로, 64(8배)·128(4배) 확대를 v2·v3 순서로, 맨 아래에 1024 두 장(밝은 배경 v2, 어두운 배경 v3). 64 px에서 v2는 눈썹·줄무늬 때문에 찡그린 얼굴로 보이고 v3는 그렇지 않다.

## 확인

- `work/app-icon-v2-preview.png`: 16 · 32 · 64 · 128 · 512 실제 크기(밝은·어두운 배경)와 16 × 8 · 32 × 4 · 64 × 2 확대. 16 px에서도 귀·세로 눈·목걸이가 구별되고, 메뉴 막대 고양이와 같은 머리로 읽힌다.
- `work/app-icon-v2-system-small.png`(`work/asset-generator system`): 빌드한 번들을 새 경로에 복사해 macOS 27.0.1의 `NSWorkspace.icon(forFile:)`로 16 · 32 · 64 · 128 pt를 @2x로 그린 결과. 0.8.0 빌드에서도 모두 회색 판 없이 마스크·그림자가 입혀진 타일로 표시되고, 16 pt에는 픽셀 머리 32 px 판이 쓰인다. 앱은 실행하지 않는다.
- `work/app-icon-v2-system.png`: 이전 라운드에 같은 NSWorkspace 방식으로 만든 큰 크기 v1·v2 비교. v1(투명 배경 머리)은 회색 스퀘어클 안에 들어가고 v2는 타일로 표시된다(이후 1024는 목걸이 색만 바뀜).
- 번들 `.icns`에서 꺼낸 16 · 32 px 항목은 원본 PNG와 알파·불투명 픽셀이 같다(부분 알파 가장자리 색만 iconutil 재인코딩으로 다름).
- 다크·틴트 모양은 시스템 자동 처리에 맡긴다(Assets.car를 만들지 않은 이유는 위 결정 참고).
